# План: перенос мессенджеров из верхних вкладок в БОКОВОЙ РЕЙЛ (API сверху, веб ниже)

> ⚠️ **РАЗВОРОТ (2026-08-13, v1.2.256) — этот план БОЛЬШЕ НЕ АКТУАЛЕН.** Пользователь отверг отдельную панель `SourceRail` + тумблер («всё в одном окне, а не в дополнительной панели»). Принята **Модель 🅰️**: веб-мессенджеры встроены в СУЩЕСТВУЮЩУЮ нативную полосу (`NativeApp` `div.native-sidebar`), `SourceRail`+флаг удалены. Актуальное решение — [[decisions]] **ADR-032**. Ниже — история подхода `SourceRail` (сохранена для контекста; код в истории git c9b72b6…d461b3f).

**Статус**: 🔴 Подход SourceRail ЗАКРЫТ (заменён Моделью 🅰️, ADR-032). История: ✅ Этап 0 + 1 + 2A + 2B + 2C + Этап 3 «умный +» (v1.2.244–255) — всё в git, но из рабочего кода удалено.
**Владелец решения**: пользователь (оператор ЦентрЧатов).
**Стек**: Electron 42.5 + Node 24, React 19.2, Vite 7, Tailwind 4 (architecture.md).

## 🎯 ЦЕЛЬ

Убрать **верхние вкладки мессенджеров** и собрать все источники в **левом боковом рейле**:
- **сверху — API-аккаунты** (Telegram/TDLib, значок ✓) → клик открывает общий чат (нативный инбокс);
- **ниже — веб-мессенджеры** (ВКонтакте / WhatsApp / MAX, значок 🌐) → клик открывает ВЕБ-интерфейс мессенджера на весь экран (API скрыт), сверху полоска «← Общий чат».

**Выбранный дизайн — «Всё сразу» (Вариант 10)** + 7 улучшений (см. ниже).
**НИ ОДНА функция вкладок не должна пропасть** — работать как раньше.

**Позже (Этап 4, отдельно)**: DOM-мост — веб-сообщения пересылаются в общий чат.

## 🗺️ КАК УСТРОЕНО СЕЙЧАС (карта кода, проверено 2026-08-13)

### Два «мира»
1. **Верхние вкладки (веб-мессенджеры)** — оркестратор `src/App.jsx`.
   - Панель вкладок: `src/components/TabBar.jsx` (шапка 48px: лого + ряд вкладок + «+» + правые иконки поиск/AI/шаблоны/настройки + нижняя `StatusBar`).
   - Одна вкладка: `src/components/MessengerTab.jsx`.
   - Точка связи: `src/components/ConnectionStatusDot.jsx`.
2. **Рейл аккаунтов (нативный TDLib)** — `src/native/NativeApp.jsx:330` (`div.native-sidebar`), ВНУТРИ вкладки `native_cc`. Аватар: `src/native/components/AccountAvatar.jsx`, меню: `AccountContextMenu.jsx`.

### Ключевые механизмы (НЕ ломать)
- **Один веб-мессенджер = один `<webview>`** (`App.jsx:737-745`). Все webview всегда «живые».
- **Переключение видимости — НАЛОЖЕНИЕ СЛОЁВ (z-index + pointer-events), НЕ прятанье** (`App.jsx:716-719`): активный `zIndex:2, pointerEvents:auto`, остальные `0/none`. 🔴 Комментарий кода: `visibility:hidden` останавливает загрузку в Chromium → чёрный экран. **z-index-подход обязателен и в новом рейле.**
- **Вкладка «ЦентрЧатов»** (`NATIVE_CC_TAB`, `src/appFallbacks.jsx:6-15`, id `native_cc`, `isNative:true`) → рендерит `<NativeApp>` вместо `<webview>` (`App.jsx:722`).
- **Список/порядок вкладок**: state `messengers` (`App.jsx:94`); дефолты `src/constants.js:3-173` (`DEFAULT_MESSENGERS`: telegram/whatsapp/vk/max с url+partition); порядок = порядок массива (DnD меняет его). Загрузка `useAppBootstrap.js` (IPC `messengers:load`), автосейв `App.jsx:405` (IPC `messengers:save`, main `mainIpcHandlers.js:70-104`, **фильтрует native**). `pinnedTabs`/`zoomLevels` — в `settings`.
- **Partition/session**: `persist:telegram|whatsapp|vk|max` (`constants.js`), инициализация `session.fromPartition/setupSession` в `mainIpcHandlers.js:79-102`. НЕ трогать (иначе разлогин).
- **Инъекция хуков**: preload `monitor.preload.cjs` читает `hooks/{type}.hook.js`; fallback `webviewSetup.js:363` (executeJavaScript). НЕ трогать.
- **Здоровье связи**: `src/utils/connectionHealth.js` — состояния `pending/ok/slow/error` (НЕ проценты!), latency в мс. Устанавливается по webview-событиям в `webviewSetup.js`. «95%» на вкладке = **зум (масштаб)**, не связь (`MessengerTab.jsx:90`).

### Рейл аккаунтов — что УЖЕ умеет (переиспользуем!)
- DnD-порядок: `NativeApp.jsx:288-304` + `src/native/utils/accountOrder.js` (localStorage).
- Контекстное меню: `AccountContextMenu.jsx` (инфо / выход `store.removeAccount` / цвет-метка 🎨).
- Непрочитанные: бейдж `AccountAvatar.jsx:88`.
- Цвет-метки: `shared/accountColors.js` + стор `nativeStore.js:220`.
- «+» логин: `NativeApp.jsx:399` → `LoginModal.jsx` → `nativeStore` (`tg:login-*`).
- Фильтр «Все»/solo/видимость аккаунтов, точка онлайн, ресайз рейла (`useAccountRailResize`).

### Верхние вкладки — что умеют (ЧЕК-ЛИСТ «НЕ ПОТЕРЯТЬ»)
Переключение (клик, `useTabManagement.js`) · «+» (`AddMessengerModal`→`App.jsx:476`) · закрытие ✕ с подтверждением (`removeMessenger`, `App.jsx:332`) · точка связи + клик→«Подключения» · пульс нового (`animate-ping`) · бейдж непрочитанных (+раздельно 💬/📢 + ✓) · зум NN% · превью/имя аккаунта · закреп 📌 · полоска загрузки · **правый клик — меню** (`useTabContextMenu.js`: перезагрузить/диагностика+логи/копировать URL/изменить/закрепить/закрыть) · **перетаскивание** (`useTabManagement.js`) · tooltip · поиск в чате (`useSearch`) · зум-хоткеи (`useWebViewZoom`) · бейдж в трее (`useBadgeSync`) · навигация из уведомлений (`useNotifyNavigation`) · нижняя статус-строка (692 всего/0 авто/зум) · правые иконки (поиск/AI/шаблоны/настройки) · AI-панель.

## 🧩 ГЛАВНОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ

Дизайн «API-аккаунты сверху, веб ниже» в ОДНОМ рейле требует **поднять рейл аккаунтов из `NativeApp` на верхний уровень (`App.jsx`)** и **объединить** его со списком веб-мессенджеров. Это суть переделки.

**Тонкость (риск):** рейл аккаунтов плотно завязан на `nativeStore` (порядок, цвета, непрочитанные, логин). Поднимаем через колбэки (`NativeApp` уже отдаёт наружу `onActiveNativeAccountChange`, `onConnectionSnapshot`), НЕ переписывая стор.

## 📅 ПЛАН ПО ЭТАПАМ

### Этап 0 — фундамент-флаг (без видимых изменений) 🟢
- Ввести настройку-переключатель `sideRail` (boolean, default **false**). Пока false — всё как сейчас (старые вкладки).
- Позволяет строить новое, не ломая рабочую версию; откат = флаг false.
- **Верхние вкладки НЕ трогаем.**

### Этап 1 — новый боковой рейл, за флагом (костяк) 🟡
- Новый компонент `src/components/SourceRail.jsx` (верхний уровень).
- Сверху API-аккаунты (данные из `NativeApp` через колбэк), разделитель, ниже веб-мессенджеры (`messengers` без native), «+».
- Клик по API → инбокс + выбор аккаунта; клик по вебу → его webview + полоска «← Общий чат».
- **Webview переключаются тем же z-index-наложением.** TabBar остаётся (пока не убираем).

### Этап 2 — перенести ВСЕ функции вкладок в рейл (чек-лист «не потерять») 🟡
**Разбит на 3 под-этапа по риску:**
- **2A ✅ СДЕЛАНО (v1.2.245)** — индикаторы на значках: бейдж непрочитанных (+💬/📢 в подсказке), точка связи (клик→Подключения), пульс нового, полоска загрузки, ✓ «прочитано», подсказка с именем аккаунта. Данные — те же, что во вкладках (переиспользование, новой логики нет). Тесты 11 + смоук.
- **2B ✅ СДЕЛАНО (v1.2.248)** — правый клик (то же меню вкладок, `position:fixed` по координатам курсора; вызов `onContextMenu(id,x,y)`→`setContextMenuTab`) + перетаскивание (те же `handleDragStart/Over/Drop/End(id)` + `dragOverId`). Тесты 16 + смоук. **Тех-долг:** меню рендерит `TabBar` — при удалении вкладок в финале вынести меню из `TabBar` (иначе правый клик в рейле перестанет открывать меню).
- **2C ✅ СДЕЛАНО (v1.2.251)** — отдельные Telegram-аккаунты значками-аватарами. `NativeApp` отдаёт наверх список (`onAccountsChange`) + действие solo (`onAccountActionsReady`); `App` → `SourceRail` рисует аватар каждого аккаунта; клик → native + `soloAccount(id)`. Тесты 21 + смоук. **Ждёт визуальной проверки** (живое переключение/аватары). ⏳ Остаётся: полоска «← Общий чат» поверх веб-окна (перенесена сюда) — не сделана.

- Точка связи, бейджи непрочитанных (+💬/📢/✓), пульс, полоска загрузки на значках рейла (переиспользовать `ConnectionStatusDot`, badge-логику).
- Правый клик: объединить меню вкладки (`useTabContextMenu`) и меню аккаунта (`AccountContextMenu`).
- Перетаскивание (переиспользовать оба механизма в своих секциях).
- Зум перенести в меню/бейдж значка. Превью/имя → tooltip. Поиск/AI/настройки/хоткеи/трей/навигация — сохранить.

### 📌 Требование на будущее (решение пользователя, 2026-08-13)
**Значки веб-мессенджеров в рейле — показывать АВАТАРКИ, как у API-аккаунтов**, а не emoji/букву. Сейчас костяк рисует emoji (`m.emoji`), запасной символ-буква отклонён пользователем. Нужно: программа должна уметь брать аватар веб-мессенджера (лого/иконку страницы, favicon или аватар залогиненного аккаунта) и рисовать его в значке рейла — единообразно с рейлом аккаунтов (`AccountAvatar.jsx`). Реализация — в Этапе 2/3 (где значки получают полноценный вид). Источник аватарки веб-мессенджера пока не определён (favicon сайта / скрин / ручная иконка) — уточнить при реализации.

### Этап 3 — улучшения 🟡
- **Умный «+» ✅ СДЕЛАНО (v1.2.254)** — «+» рейла раскрывает выбор ✈️ Telegram-аккаунт (→ `openLogin`, отдан наверх из NativeApp) / 🌐 веб-мессенджер (→ существующее окно). Инлайн-варианты (в ширину рейла). Разблокирует добавление Telegram-аккаунтов из рейла → пользователь может протестировать переключение аккаунтов. Тесты 23+5.
- **Сворачивание рейла ⬜** — низкий приоритет (рейл уже узкий 64px), отдельно.
- **Заглушить источник ⬜** — веб→`settings.mutedMessengers` (инфраструктура есть), API→помьютить аккаунт; трогает общее меню `buildTabContextMenuItems` + `handleTabContextAction` — отдельным заходом.

### (историческая формулировка «7 улучшений») 🟡
1. **Полоска активного слева** (пилюля, как Discord) — новое.
2. **Перетаскивание порядка** — переиспользовать (есть в обоих мирах).
3. **Правый клик — меню** — объединённое (из Этапа 2).
4. **Умный «+»** — выбор «Telegram-аккаунт (API)» / «Веб-мессенджер».
5. **Пульс при новом** — переиспользовать `animate-ping`.
6. **Сворачивание рейла** — расширить ресайз (`useAccountRailResize`): узкий значки ↔ широкий с именами.
7. **Заглушить источник** — в меню: веб→`settings.mutedMessengers` (уже есть), API→помьютить аккаунт (может потребовать доработки).

## ⚠️ ОПАСНЫЕ ЗОНЫ

- 🔴 **Загрузка webview / чёрный экран.** Нельзя прятать неактивные webview `display:none`/`visibility:hidden` (`App.jsx:718`). Только z-index-наложение.
- 🟡 **Связь рейла с `nativeStore`** — подъём аккаунтов наверх через колбэки, не переписывая стор.
- 🟡 **Сессии/partition** — не трогать (`mainIpcHandlers.js:79-102`), иначе разлогин веб-аккаунтов.
- 🟡 **`messengers:save` фильтрует native** — не сломать фильтр (иначе задвоение).
- 🟢 Данные пользователя (заметки/закрепы/настройки) не трогаем.
