### v1.2.453 — ДОВОДКА ПО РЕВЮ: экран «Нет связи» держался только до первой попытки + две новые беды, внесённые прошлой правкой

**Коммит**: `ad3d08b` (ветка `feature/virtualization`, 2026-09-11). Приложение при разработке не запускалось — правило проекта; всё доказано тестами.

**КОНТЕКСТ**: придирчивое ревью v1.2.452 нашло **три** бага, все воспроизведены падающими тестами ДО починки. Два из них внесла сама правка v1.2.452.

**№1 🔴 Экран «Нет связи» исчезал на НАШЕЙ ЖЕ второй попытке, повторы прекращались**
Защита от «эха страницы-ошибки» работала только на первом сбое.
ДВЕ причины (обе доказаны тестом):
- `planTrying` переносит запись целиком (`{ ...base }`), то есть метка времени сбоя оставалась **от первого сбоя**, а обработчик сбоя при идущей попытке возвращал запись как есть → через 5 с метка старше окна ожидания → эхо снова сходило за успех. В журнал при этом попадала ЛОЖНАЯ строка «связь восстановлена за 5с»;
- отчёт «загрузилась» от страницы-ошибки приходит **раньше**, чем отклоняется обещание `loadURL`, а состояние «идёт попытка» через `setState` применяется не мгновенно → обработчик видел прежнюю фазу.
ФИКС: (а) новое решение [shouldAcceptLoaded()](../../shared/reconnectPlan.js) — событию «загрузилась» не верим ни пока идёт наша попытка (там истину говорит только обещание `loadURL`), ни в первые 2 с после сбоя; (б) [touchFailedAt()](../../shared/reconnectPlan.js) — метка освежается на КАЖДОМ сбое; (в) фаза «идёт попытка» помечается СРАЗУ и в зеркале записей (`stRef`), поэтому порядок событий больше не важен. Нового хранилища не добавлено — `useRef` в файле ровно 2 (иначе снова сломалась бы горячая перезагрузка, см. v1.2.452).

**№2 🔴 Мигание интернета перезагружало РАБОТАЮЩЕЕ приложение** (внесено v1.2.452)
После успешного запуска заставка (вместе с панелью переподключения) удаляется из окна. Флаг «окно показано» поднимался ДО проверки, есть ли панель, — поэтому короткая пропажа сети поднимала флаг, а возврат сети делал `location.reload()`. Цена — потеря недописанного сообщения и состояния.
ФИКС ([index.html](../../index.html)): флаг поднимается ТОЛЬКО когда панель реально на экране; `ok()` (успешный запуск) его сбрасывает; обработчик возврата сети дополнительно проверяет, что панель видима. Две независимые защиты — тест падает, только если снять обе.

**№3 🔴 Запуск БЕЗ интернета крутил перезагрузки вместо запуска** (внесено v1.2.452)
Окно поднималось по одному факту «сети нет» → отсчёт → перезагрузка → сети по-прежнему нет → снова, и счётчик попыток рос 1→2→3. А оболочка приложения грузится с диска, чаты есть в памяти — без интернета программа обязана просто запуститься.
ФИКС: «нет сети» САМА ПО СЕБЕ окно больше не поднимает. Окно поднимается только при НАСТОЯЩЕМ сбое загрузки файла программы (или по предохранителю 3 минуты), а отсутствие сети лишь уточняет причину: «нет связи с интернетом — часть программы не загрузилась».

**№4 🟡 Отказ был «немым»**: отброшенное ложное восстановление не попадало в журнал — теперь пишется `[reconnect] <имя>: пришла страница-ошибка, а не сама страница — восстановлением не считаю` (уровень TRACE).

**№5 🟡 Хрупкий порядок объявлений** в `index.html`: «пульт» окна (`window.__ccBootNet`) использовался обработчиками раньше, чем создавался. Не падало только потому, что пауза всегда ≥5 с. Пульт объявлен ДО слушателей; тест сторожит порядок.

**№6 🟡 Три места по-разному реагировали на возврат сети** (хук мессенджеров, полоса «Общего чата», окно запуска) — именно это породило №2. Закрыто фиксом №2: перезагружать окно имеет право только окно запуска и только когда оно показано.

**РАЗГРУЗКА (правило проекта: не резать комментарии, а выносить)**: хук дорос до 167 строк при потолке 150 → в [shared/reconnectPlan.js](../../shared/reconnectPlan.js) (193 → 264/300) вынесены `shouldAcceptLoaded`, `touchFailedAt`, `messengerInfo`, `logEchoLine`, `isErrorPageEcho`. Хук стал **150 строк**; для него оформлен потолок 170 с обоснованием ([fileSizeLimitsExceptions.cjs](../../src/__tests__/fileSizeLimitsExceptions.cjs)): остаток — проводка и комментарии-ловушки, которые резать нельзя.

Заглушка страницы в тестах теперь ведёт себя КАК В ЖИЗНИ: при неудачной загрузке сначала присылает события своей страницы-ошибки, и только потом отклоняет обещание — без этого прошлые тесты бага не видели.
Итог: `reconnectPlan.vitest.js` **31/31**, `useWebviewReconnect.vitest.jsx` **24/24**, `bootNet.vitest.js` **23/23**; цепочка 47 тестов — 0 падений; полный `vitest run` 202 файла / 2696 тестов; линт 0; лимиты 642/642; установщик пересобран.
Обе главные ловушки проверены «наоборот»: при откате фикса падают (для №2 — только если снять обе защиты, что и подтверждает двойной запас).

**ПЕРЕСМОТРЕННЫЙ УГОВОР** (важно помнить): «нет сети» — НЕ повод показывать окно переподключения приложения. Повод — только настоящий сбой загрузки файла программы. Пять старых тестов, закреплявших прежний уговор, переписаны осознанно.

**ЧТО ПРОВЕРИТЬ ВРУЧНУЮ**: (1) полный перезапуск; (2) выключить Wi-Fi при открытом мессенджере → экран держится и после 5-10-20 секунд, в журнале НЕТ слова «восстановлена», зато есть «попытка N не удалась»; (3) поработать в приложении и мигнуть сетью → окно НЕ должно перезагружаться; (4) запустить без интернета → приложение должно просто запуститься.

**Откат**: `git revert` коммита. Отдельно вернуть прежнее поведение окна — вернуть показ по `offline` в `index.html` (но тогда вернётся петля перезагрузок).

**ОСТАТОЧНЫЕ РИСКИ**: (а) 🟡 живьём не воспроизводилось — правило проекта запрещает мне запускать приложение; всё доказано тестами на настоящем коде; (б) 🟡 окно 2 секунды подобрано по замеру из журнала (30-60 мс) — если мессенджер поднимется сам быстрее 2 с, экран снимется на 2 с позже; (в) 🟢 хук стоит на 150/170 — следующий рост требует выноса `attempt()` узлом связей.

### v1.2.452 — 🔴 ОБРЫВ СВЯЗИ ПРИ ЗАПУСКЕ: приложение больше не висит на заставке + экран «Нет связи» у мессенджеров наконец ДЕРЖИТСЯ

**Коммит**: `ad3d08b` (ветка `feature/virtualization`, 2026-09-11). Приложение при разработке не запускалось — правило проекта; всё доказано тестами.

**ЖАЛОБА (11 сентября 2026)**: «почему во время запуска через терминал не запустилось, были проблемы с интернетом, а потом восстановились» + «надо, чтобы окно переподключения было автоматическое, то же самое как на мессенджеры».

**ПРИЧИНА №1 — почему не запустилось (🟢 доказано журналом, не догадка)**
Запуск 09:03:09 (dev, код грузится с dev-сервера по одному файлу). В 09:04:56 — **14 файлов программы разом не догрузились** с `net::ERR_NETWORK_CHANGED` (сеть переключилась):
```
dev-request failed id=68 err="net::ERR_NETWORK_CHANGED" type=script url=/src/components/CcMark.jsx
dev-request failed id=71 err="net::ERR_NETWORK_CHANGED" type=script url=/shared/reconnectPlan.js
… ещё 12 файлов
[startup-renderer] splash +180018ms safety hid splash: дальний предохранитель 180с (appReady не наступил)
```
Сорванная загрузка файла программы НЕ повторяется сама — цепочка подключений порвалась, `appReady` не наступил никогда, а через 3 минуты предохранитель просто убрал заставку → **пустое окно**. Перезапуск в 09:10 прошёл нормально (886 чатов).
**Важно**: это беда только запуска ИЗ ТЕРМИНАЛА (dev). В установленной версии код лежит на диске и по сети не грузится — такого сбоя там быть не может. Но окно переподключения полезно и там (любой иной сбой запуска).

**ФИКС №1 — авто-окно переподключения для САМОГО приложения** ([index.html](../../index.html) 101 → 214/800)
```
┌──────────────────────────────────────────────┐
│  Не удалось загрузить приложение             │
│  часть программы не загрузилась — похоже,    │
│  пропала связь                               │
│  Повторим через 5 с      [Повторить сейчас]  │
│  Попытка 1 — программа пробует сама          │
└──────────────────────────────────────────────┘
```
Поднимается САМО по трём признакам: (1) файл программы не загрузился — событие `error` в фазе перехвата (🥇 MDN: «событие ресурса не всплывает», поэтому именно перехват); (2) сорванная догрузка — отказ обещания (`Failed to fetch dynamically imported module`); (3) сеть пропала (`offline` / `navigator.onLine === false`). Лестница пауз **та же, что у мессенджеров** (5/10/20/40/60 с), номер попытки живёт в памяти окна и переживает перезагрузку, возврат сети → повтор сразу, при успехе счётчик обнуляется ([main.jsx](../../src/main.jsx) зовёт `ok()`). Предохранитель 3 минуты в [boot-probe.js](../../src/boot-probe.js) теперь показывает ЭТО окно вместо пустоты.

**🔴 ПОЧЕМУ КОД ВНУТРИ `index.html`, А НЕ В МОДУЛЕ**: среди не догрузившихся файлов был и `shared/reconnectPlan.js`. Значит код окна не может ничего у себя подключать — упадёт вместе с остальным. `index.html` — сам документ, ему загружать нечего. Цена: числа лестницы дублируются, поэтому их совпадение с единым источником сторожит тест (проверено на подмене: 3 падения).

**ПРИЧИНА №2 — экран «Нет связи» у мессенджеров НЕ РАБОТАЛ (🔴 мой баг из v1.2.445, найден в том же журнале)**
```
18:59:04 [reconnect] WhatsApp: обрыв связи, код=-105 ERR_NAME_NOT_RESOLVED, попытка 1 через 5с
18:59:04 [reconnect] WhatsApp: связь восстановлена за 0с (попыток: 1)   ← через 30 мс!
```
Сразу после неудачи Chromium показывает свою **страницу-ошибку**, и у неё тоже случается событие «загрузилась». По доке Electron это событие значит лишь «переход завершён и сработал onload» — ЧТО загрузилось, оно не сообщает. Итог: экран мелькал 30 мс и исчезал, лестница повторов не запускалась, мессенджер оставался на странице-ошибке — **вся функция v1.2.445 не работала**, и это же объясняет исходную жалобу «вместо WhatsApp вижу Telegram».

**ФИКС №2** ([shared/reconnectPlan.js](../../shared/reconnectPlan.js) 193 → 227/300, [useWebviewReconnect.js](../../src/hooks/useWebviewReconnect.js) 135 → 146/150)
- Новая чистая проверка `isErrorPageEcho(запись, сейчас)` + `ERROR_PAGE_GRACE_MS = 2000`: событию «загрузилась» в первые 2 с после сбоя НЕ верим. Момент сбоя (`failedAt`) лежит В САМОЙ ЗАПИСИ.
- Признаки настоящего успеха: разрешённое обещание `loadURL` (наша попытка) ИЛИ событие ПОЗЖЕ окна ожидания (страница поднялась сама).
- Заодно: сбой **вложенного кадра** (реклама, встроенное окошко) больше не поднимает экран — проверяется документированное поле `isMainFrame`.

**🔴 ГРАБЛЯ, КОТОРУЮ Я ПОЙМАЛ НА СЕБЕ ПО ХОДУ**: первая версия фикса №2 добавляла в хук новое хранилище (`useRef`). У пользователя тут же выскочило «Should have a queue.
