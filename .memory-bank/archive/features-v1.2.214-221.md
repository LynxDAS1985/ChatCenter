### v1.2.221 — Лента уведомлений: не дёргать список при чтении + видимая полоса прокрутки

Дата: 2026-08-11. Жалоба: оставил программу на ночь, накопилось 30+ уведомлений — и не нажимается НИ одна кнопка (✕, «Прочитано», «Перейти», AI).

**Корень (по коду + живому логу):** список карточек авто-прокручивался в самый низ на КАЖДОЕ новое уведомление — `scrollContainerToLatest()` безусловно ставил `container.scrollTop = scrollHeight` ([notification.js:22-26](../main/notification.js)) и вызывался в конце `addNotification` ([notification.js:642](../main/notification.js)). При ночном потоке (в логе — 3 уведомления за одну секунду, `addNotification id=107..109`) список постоянно дёргается вниз, и клик попадает в «уехавшую» кнопку → нажатие не проходит. Плюс общая высота карточек упиралась в потолок экрана (`[notif-resize] CLAMP rawHeight=11014 displayHeight=796`), а полоса прокрутки была почти невидимой (6px, alpha 0.22) — непонятно, что список можно листать.

**Что изменено:**
- **Умный авто-скролл.** Новая чистая `shouldAutoScroll({scrollHeight,scrollTop,clientHeight})` в [notification-helpers.js](../main/notification-helpers.js): вниз прокручиваем ТОЛЬКО если юзер уже у низа списка (порог 90px). Прокрутил вверх (читает старые) → список НЕ дёргаем. `scrollContainerToLatest` использует её. Факт уровня 1 (MDN): «у низа» = `scrollHeight − scrollTop − clientHeight ≈ 0`.
- **Видимая полоса прокрутки.** [notification.css](../main/notification.css): ширина 6→10px, thumb ярче (alpha 0.42, min-height 40px, hover 0.6), track чуть виден — сразу ясно, что снизу есть ещё карточки.

Модель «фикс. высота (доля экрана) + прокрутка внутри `#container`» и лимит 30 карточек существовали ранее (v1.2.54) — здесь чинится их поведение при потоке. Ресайз/`rendererPure`/группировку НЕ трогали (минимальное касание фрагильной «саги»).

**Отложено:** пузырь-подсказка «↓ N новых» при чтении — `notification.js` на пределе (728/730), добавление требует разбиения файла (отдельная задача-риск). Отдельный «клик мёртв на СТАБИЛЬНОМ списке без новых» (если он есть) этой правкой не адресуется — доказанный корень именно в авто-дёрганье при потоке; при повторе на стабильном списке нужен живой репро.

**КАК ПРОВЕРЕНО:** тест `albumLiveCard.vitest.js` +4 (`shouldAutoScroll`: у низа→true, вверху→false, порог 90/91, непрокручиваемый→true) → 26/26; линт 0; лимиты 562/562; `notifResizeDecision` 6/6; `notifHooks` 87/87. Живьём (окно уведомлений не тестируется без запуска) → **требует перезапуска + визуальной проверки**: при потоке список не прыгает, полоса видна, кнопки нажимаются. Немедленное облегчение сейчас — перезапуск (лента в памяти, очистится). Откат: `git checkout -- main/notification.js main/notification-helpers.js main/notification.css src/__tests__/albumLiveCard.vitest.js` + версия на 1.2.220. См. граблю [[notifications-ribbon]].

### v1.2.219 — Фантомная «1 непрочитано» в ВК: счётчик перестал считать бейджи «Друзья/Игры»

Дата: 2026-08-10. Жалоба: в верхней полоске у ВК висит «1 непрочитано [ВКо:1]», хотя в мессенджере непрочитанных нет (сообщение никуда не открывается, «1» не гаснет).

**Корень (по коду + живому логу):** счётчик непрочитанных ВК `countUnreadVK` ([unreadCounters.js](../main/preloads/utils/unreadCounters.js)) в последнем, самом грубом методе (метод 4) перебирал `UNREAD_SELECTORS.vk`, где стояли ОБЩИЕ приметы VKUI-бейджей `.vkuiCounter` и `.vkuiBadge`. Такие бейджи VK рисует ПО ВСЕЙ странице — в т.ч. «Друзья 1» и «Игры 1» в левом меню и колокольчик уведомлений. `document.querySelectorAll('.vkuiCounter')` не привязан к мессенджеру → метод 4 суммировал чужие бейджи и возвращал фантомную «1». Это число уходит в полоску через [monitor.preload.cjs:235,247](../main/preloads/monitor.preload.cjs) (`countUnread` → `unread-count`). Диагностика `__CC_DIAG__vk-src` в [vk.hook.js](../main/preloads/hooks/vk.hook.js) в живом `chatcenter.log` (2026-08-10) показала `titleN=нет msgBadge=0 friends=1 games=1 step3=нет` → методы 1–3 дали ноль, ненулевые только Друзья/Игры → значит виноват метод 4 с общими приметами.

**Фикс:** из `UNREAD_SELECTORS.vk` убраны `.vkuiCounter` и `.vkuiBadge`; оставлены только приметы, привязанные к мессенджеру/чатам (`.ConversationItem__unread`, `.im_nav_badge`, legacy `.im-page--chat-unread-count`, `.MessagesNavItem--unread …`). Реальное непрочитанное ВК по-прежнему берётся из заголовка вкладки «(N)» (метод 1) и бейджа пункта «Мессенджер» (метод 2), поэтому настоящие сообщения не потеряются. Telegram/MAX/WhatsApp не затронуты.

**КАК ПРОВЕРЕНО:** сторож-тест в `monitorPreload.test.cjs` (VK-приметы не должны содержать общих `.vkuiCounter`/`.vkuiBadge`) → 106/106; линт; лимиты 561/561 (`unreadCounters.js` 273/500). Живьём (полоска станет «0» при пустом мессенджере) без запуска не проверить → **требует перезапуска + визуальной проверки**. Остаток (маловероятно): если на каком-то экране vk.ru реальное непрочитанное показывается ТОЛЬКО общим `.vkuiCounter` и не попадает ни в заголовок, ни в бейдж «Мессенджер» — тогда добавим приметы, но ПРИВЯЗАННЫЕ к мессенджеру (в контейнере чатов), а не по всей странице. ### v1.2.216 — «Перейти в чат» по клику уведомления ВК чинится под vk.ru + имя мессенджера в статусе

Дата: 2026-08-07. Жалоба: при клике по уведомлению ВК плашка пишет «Х «Елена Дугина» — не найден в списке», хотя чат есть; и в плашке не видно, какой мессенджер.

**Корень (по коду):** искалка «перейти в чат» для ВК ([navigators/vkNavigate.js](../src/utils/navigators/vkNavigate.js)) искала строку списка по жёстким приметам старого vk.com (`.im_dialog_peer`, `PeerName`, `.ConvoListItem__title`) и сверяла имя «символ-в-символ». Провал отправки (send-failed) шлёт тот же `oldId` → на частичном сбое тоже не виснем. Чужие подтверждения игнорируются (сверяем только свои номера).
