### v1.2.405 — Заставка загрузки чатов на ВСЁ окно (была в области чата, сбоку от полосы аккаунтов)

**ЗАЧЕМ**: жалоба — заставка с аватарками+счётчиком показывалась «в окне чата» (в области контента), а полоса аккаунтов торчала слева; надо в БОЛЬШОМ окне (как «второй экран» NativeAppFallback). **КОРЕНЬ (по коду, 🟢)**: `ChatListLoadingSplash` рендерится в `InboxMode` (область список+чат), а полоса аккаунтов рисуется ОТДЕЛЬНЫМ порталом на уровень App ([NativeApp.jsx:361](src/native/NativeApp.jsx) `createPortal` в `#app-native-rail`). CSS `.native-chatload` был `position:absolute` (относительно InboxMode) → заставка накрывала только список+чат, полоса оставалась видна сбоку. «Второй экран» (NativeAppFallback) был на всё окно, т.к. рисуется ДО монтирования NativeApp (полосы ещё нет).

**ЧТО** ([styles-chatlist-loading.css](src/native/styles-chatlist-loading.css)): `.native-chatload` — `position:absolute` → **`position:fixed; inset:0; z-index:9000`** → заставка перекрывает ВСЁ окно (полосу аккаунтов + список + чат + верхнюю панель), как второй экран. z-index ниже стартовой заставки (99999). Компонент НЕ двигал — только позиционирование. Проверено: на нативных контейнерах нет статического `transform` (только keyframes у WhatsNewModal) → `fixed` корректно относительно окна.

**КРАЙНИЕ СЛУЧАИ**: `--amoled-*` переменные доступны (элемент всё ещё в дереве `.native-mode`, `fixed` меняет только позицию) + фолбэки в CSS; `--leaving` fade и pointer-events работают. **КАК ПРОВЕРЕНО**: `lint` 0; `ChatListLoadingSplash.vitest` 8/8; `fileSizeLimits` 602/602; полный `vitest`. **Требует визуальной проверки**: перезапуск → анимация загрузки на ВСЁ окно (полосы аккаунтов сбоку не видно). **Остаточный риск**: если у окна есть редкий CSS-эффект на предке (filter/contain/transform во время анимации монтирования) — `fixed` может привязаться к предку; тогда портал в body. **ОТКАТ**: `git checkout src/native/styles-chatlist-loading.css` + версия 1.2.404.

### v1.2.404 — Загрузка чатов: ВИДИМАЯ анимация (счётчик реально растёт 0→N, аватарки по одной за ~3.5с) + убран «третий» generic-экран

**ЗАЧЕМ**: жалоба — счётчик стоял «0 из 890», потом МГНОВЕННО список; загрузка «не идёт»; плюс «третий экран». КОРЕНЬ (по коду + журналу, 🟢): чаты приходят из кэша ОДНИМ пакетом в самом конце (loadCachedChats/loadChats резолвится разом), а `chatsFirstLoadDone` наступает почти одновременно → счётчик привязан к `chatsLen`, который прыгает 0→N ровно когда заставка ГАСНЕТ → «загрузки» не видно. Реального «по одному» у чатов нет — долго грузится КОД (dev ~2 мин), а чаты — миг. «Третий экран» — промежуточный generic `NativeAppFallback` между стартовой и нашим экраном (v1.2.403 снимал стартовую на appReady).

**ЧТО (видимая анимация + один экран)**:
1. [ChatListLoadingSplash.jsx](src/native/components/ChatListLoadingSplash.jsx): счётчик/аватарки/полоса теперь гонит `progress` 0→1 за ~3с (rAF, React docs «Synchronizing with Effects»), НЕ привязан к моменту прихода данных. Счётчик растёт 0→total, аватарки проявляются ПО ОДНОЙ (`revealed = round(progress·5)`), полоса заполняется. `MIN_VISIBLE` 2200→**3500мс** — держим заставку ≥3.5с, чтобы анимация (≈3с) прошла НА ГЛАЗАХ, а не мелькнула.
2. Убран «третий экран»: стартовую заставку (`index.html`) снова НЕ снимаем на appReady ([useAppBootstrap.js](src/hooks/useAppBootstrap.js)); её убирает наш экран при показе ([ChatListLoadingSplash.jsx] `__ccHideSplash`) + запасной таймер 0.8с в [NativeApp.jsx](src/native/NativeApp.jsx). Итог: «ЦентрЧатов» → СРАЗУ анимация загрузки (без generic-экрана) → список.

**ЧЕСТНО**: анимация — «красивая индикация», а не реальный счёт по одному чату (чаты приходят пакетом; реального пошагового прогресса нет). Так делают многие приложения (минимальная анимация загрузки). Задержка старта +~3.5с (осознанно — ради видимой загрузки). В dev стартовая «ЦентрЧатов» всё равно долгая (грузится код), анимация — после неё.

**КРАЙНИЕ СЛУЧАИ**: 0 аккаунтов → запасной таймер 0.8с снимает стартовую; total=0 (первый запуск) → «Собираем чаты…»; данные грузятся дольше 3с → progress=1 (счётчик на total, все аватарки), ждём завершения; `prefers-reduced-motion` → без анимаций. **КАК ПРОВЕРЕНО**: `lint` 0; `ChatListLoadingSplash.vitest` 8/8; `fileSizeLimits` 602/602; полный `vitest`. **Требует визуальной проверки**: перезапуск → «ЦентрЧатов» → видимая анимация (счётчик растёт, аватарки по одной, полоса) ≥3с → список; промежуточного generic-экрана нет. **ОТКАТ**: `git checkout src/native/components/ChatListLoadingSplash.jsx src/hooks/useAppBootstrap.js src/native/NativeApp.jsx` + версия 1.2.403.

### v1.2.403 — Загрузка чатов по согласованному макету: кружки на ВСЮ загрузку + аватарки проявляются + счётчик РАСТЁТ (откат v1.2.402)

Надо: старт «ЦентрЧатов» → кружки бегают всю сборку → на них ПРОЯВЛЯЮТСЯ аватарки + РАСТЁТ счётчик «Загружено N из M» → список.

**ЧТО**:

Теперь после appReady видна ЖИВАЯ заставка кружков (NativeAppFallback → ChatListLoadingSplash) на всю загрузку, а не бренд-заставка.
2. **Счётчик РАСТЁТ** ([ChatListLoadingSplash.jsx](src/native/components/ChatListLoadingSplash.jsx)) — новое `displayCount` плавно анимируется от 0 к реальному числу чатов за ~1.2с (rAF в useEffect+cleanup, React docs «Synchronizing with Effects»), даже если чаты пришли из кэша разом. 4. **Прогресс-полоса** под счётчиком (как на макете) — в ChatListLoadingSplash и на раннем экране.

**ЧЕСТНЫЙ ПРЕДЕЛ (в макете отмечен)**: реальные аватарки и точный счётчик появляются, когда загрузился код чат-части; в dev это ближе к концу (~2 мин грузится код). Но кружки бегут ВСЮ загрузку (ранний экран), а аватарки+рост счётчика — когда данные пришли. В установленной сборке всё быстро и плавно.

**КРАЙНИЕ СЛУЧАИ**: 0 аккаунтов → кружки generic + «Готовим…»; hint=0 (первый запуск) → «Собираем чаты…» без «из N»; happy-dom тест (rAF не бежит) → счётчик остаётся 0 (тест ждёт `\d+ из 1`). **КАК ПРОВЕРЕНО**: `lint` 0; `ChatListLoadingSplash.vitest` 8/8; `startupDiagnostics` 4/4; `rendererConsoleGuard` 0; `fileSizeLimits` 602/602 (бюджет 35580); полный `vitest`. **Требует визуальной проверки**: перезапуск → «ЦентрЧатов» → кружки бегут → аватарки проявляются + счётчик растёт + полоса → список. **ОТКАТ**: `git checkout src/hooks/useAppBootstrap.js src/native/NativeApp.jsx src/native/components/ChatListLoadingSplash.jsx src/appFallbacks.jsx src/native/styles-chatlist-loading.css` + версия на 1.2.402.

### v1.2.402 — Загрузка чатов: ОДИН экран вместо двух — стартовая заставка держится до появления нашего экрана чатов (бесшовно)

**ЗАЧЕМ**: жалоба — всё ещё ДВА экрана загрузки чатов подряд: (1) кружки БЕЗ аватарок «Загрузка чатов…» (`NativeAppFallback`), (2) кружки С аватарками+счётчиком «Загружаем X… Загружено N из M» (`ChatListLoadingSplash`). Хотели ОДИН: кружки бегают, по мере загрузки на них появляются аватарки, счётчик — там же.

**КОРЕНЬ (по коду, 🟢)**: это ДВА разных компонента, сменяющих друг друга на границе загрузки кода нативного интерфейса. `NativeAppFallback` показывается, ПОКА грузится код NativeApp (у него НЕТ данных чатов → generic-кружки). `ChatListLoadingSplash` (реальные аватары+счётчик) — ВНУТРИ NativeApp, показывается ПОСЛЕ его монтирования. Стартовую заставку (`index.html #cc-splash`) снимали на `appReady` ([useAppBootstrap.js:92](src/hooks/useAppBootstrap.js)), а NativeApp монтируется ПОЗЖЕ appReady → между ними виден generic-экран `NativeAppFallback`. Отсюда «два экрана».

**ЧТО (Вариант «стартовая держится до нашего экрана»)**:
1. [useAppBootstrap.js:92](src/hooks/useAppBootstrap.js): убран вызов `window.__ccHideSplash?.()` на appReady — стартовая заставка НЕ снимается раньше времени.
2. [ChatListLoadingSplash.jsx](src/native/components/ChatListLoadingSplash.jsx): когда наш экран чатов ПОКАЗАЛСЯ — сам зовёт `window.__ccHideSplash?.()` → БЕСШОВНАЯ передача (стартовая гаснет ровно когда появляются кружки+аватары+счётчик; промежуточного generic-экрана НЕ видно).
3. [NativeApp.jsx](src/native/NativeApp.jsx): запасное снятие стартовой через 0.8с после монтирования — на случай 0 аккаунтов (заставка чатов не покажется) → не застреваем на стартовой.

**ИТОГ**: старт «ЦентрЧатов/Загрузка…» (бренд) → ОДИН экран чатов (кружки с аватарами + «Загружено N из M») → список. Generic-кружки `NativeAppFallback` больше не видны (перекрыты стартовой до появления нашего экрана). **ЧЕСТНО про «аватарки появляются по мере загрузки»**: чаты грузятся из КЭША разом, поэтому аватары появляются на кружках сразу при показе экрана (не по одному) — это предел (кэш отдаёт всё сразу), но экран ОДИН.

**КРАЙНИЕ СЛУЧАИ**: 0 аккаунтов → запасной таймер 0.8с снимает стартовую; заставка чатов не покажется, но и не нужна. Если `__ccHideSplash` не вызовется вовсе — ловит дальний предохранитель boot-probe 180с. **КАК ПРОВЕРЕНО**: `lint` 0; `ChatListLoadingSplash.vitest` 8/8; `startupDiagnostics` 4/4; `fileSizeLimits` 602/602; полный `vitest`. **Требует визуальной проверки**: перезапуск → «ЦентрЧатов/Загрузка» → сразу наш экран (кружки+аватары+счётчик), БЕЗ промежуточного generic-экрана. **ОТКАТ**: `git checkout src/hooks/useAppBootstrap.js src/native/NativeApp.jsx src/native/components/ChatListLoadingSplash.jsx` + версия на 1.2.401.
