### v1.2.488 — Предел «вечных» карточек уведомлений — по РЕАЛЬНОЙ высоте, не по числу «180 точек на карточку»

**ОТ ПОЛЬЗОВАТЕЛЯ**: «предел карточек считает 180 точек на карточку, раскрытая — до 420 → стопка втрое выше
экрана — делай, фиксируй в документах». Смежный пункт дела [notif-window-input-loss-case.md](./notif-window-input-loss-case.md)
(это НЕ лечение обрыва мыши — он расследуется отдельно; это устранение усилителя неудобства).

**Было**: `MAX_PERSISTENT_ITEMS = max(6, min(14, availHeight/180))` → на экране 816 = **6** карточек по числу.
Раскрытая карточка (настройка «раскрывать сразу») — 130…420 точек по длине текста → 6 штук = 1083…2516
точек при окне 796 (журнал 19.09): часть карточек за краем, при новой стопка прокручивается.

**Стало**: число-предел остаётся внешним потолком (его требует страж `notificationWindowBounds.test.cjs`), а
ВНУТРИ него — второй предел по фактическим высотам ([notification-helpers.js](../main/notification-helpers.js)):
перед добавлением новой «вечной» карточки меряем `offsetHeight` каждой карточки, резервируем место под новую
(высота самой свежей, но не меньше 160), и убираем старейшие, пока `стопка + резерв ≤ availHeight − 20`
(те же поля, что у main: `NOTIF_SCREEN_MARGIN=10`). Одну карточку оставляем всегда. Гаснущие сами
(`dismissMs>0`) не затронуты — их предел 6 как был. В журнал — `trim-by-height: карточек=N высота=… бюджет=… →
убираю старейшую`. В [notification.js](../main/notification.js) — цикл из 3 строк рядом с прежним (714 → 719/730).

| ❌ Было (журнал 19.09) | ✅ Станет |
|---|---|
| 6 раскрытых = 2516 точек при экране 796, 3 карточки за краем | стопка ≤ 796: например 2 раскрытых по 400 + новая |
| предел один — по числу | два предела: по числу (внешний) и по высоте (внутренний) |

**Два способа**: (А) уменьшить делитель 180 → 420 в числе-пределе: одна цифра, но снова «средняя карточка»,
а они от 130 до 420 — при коротких текстах резали бы лишнее; (Б) мерить реальную высоту — чуть больше кода,
но честно для любых текстов. Выбрано **Б**.

### v1.2.486 — Ширина списка чатов слушается окна (TODO-40 закрыт) + диагностика жалобы «крестик не закрывает уведомление»

#### 1. 🔎 Жалоба «программа не даёт закрыть уведомления» — причина ПОКА НЕ НАЙДЕНА, поставлена диагностика

**Что установлено фактом** (журнал `chatcenter.log`, 19.09.2026):

| Факт | Значение |
|---|---|
| 18 сентября карточки закрывались | **25** записей `dismiss start … fromMain=false` |
| 19 сентября, 12:22 → 13:58 (стопка из 6 карточек) | **НИ ОДНОЙ** такой записи |
| Число карточек за этот день | `items=6 containerChildren=6` — не изменилось **ни разу** |
| После перезапуска в 14:02 | первое же закрытие прошло (`dismiss start id=1 itemsBefore=1`) |
| Настройки пользователя | `notifDismissSec = 0` (не закрывать самим — ЭТО ВЫБОР ПОЛЬЗОВАТЕЛЯ, не дефект), `ribbonExpandedByDefault = true` |
| Высота стопки против окна | `rawHeight` 1083…2516 при `displayHeight=796` — стопка в 1,5–3 раза **выше экрана** |

**Вывод**: функция закрытия (`dismissItem`) даже не начиналась. Отличить «нажатие не дошло до
кнопки» от «кнопка сработала, а функция вышла в первой строке» было **нечем**: оба ранних выхода
(`!item`, `item.dismissing`) стоят ДО первой записи в журнал.

**Что добавлено** (поведение не меняется — только записи):
- `logCloseClick` — на каждое нажатие крестика: дошло ли, есть ли карточка в списке, не помечена ли
  она «уже закрывается», сколько карточек, и **прокрутка** `scrollTop/clientHeight/scrollHeight`
  (стопка бывает выше окна — тогда часть карточек физически за краем);
- `logDismissSkip` — оба молчаливых отказа теперь пишутся предупреждением с причиной;
- `installNotifErrorReporter` — 🔴 **закрыта слепая зона**: падения кода ВНУТРИ окна уведомлений
  раньше не попадали в журнал вообще (`console.*` окна туда не пишет, перехвата ошибок не было).
  Если обработчик кнопки не навесился из-за ошибки выше по коду — теперь это видно строкой.

Подробный снимок карточек перенесён из `notification.js` (стоял **729/730**, ни одна новая строка
не влезала) в [notification-helpers.js](../main/notification-helpers.js) → `notification.js` **714/730**.

#### 2. ✅ TODO-40 закрыт: ширина списка чатов подстраивается под окно на лету

Было: потолок «не шире 40 % окна» считался только при загрузке настроек, при перетаскивании и при

Стало: [useChatListResize.js](../src/native/hooks/useChatListResize.js) слушает изменение окна и
пересчитывает ПОКАЗАННУЮ ширину от ЖЕЛАЕМОЙ (из настроек).

| ❌ Было | ✅ Стало |
|---|---|
| сузил окно → список широкий, переписка зажата | список ужимается сразу |
| вернул окно → ширина не вернулась | вернулась к своей (из настроек) |
| — | сохранённая ширина **не портится** (в настройки ничего не пишем) |

🔴 Почему не правилом вёрстки (как у панели ИИ): «узкий вид» списка решается по ЭТОМУ ЖЕ числу —
уменьшив только показанную ширину, получили бы узкую панель с широкими строками внутри.
🔴 Почему не пишем в настройки: иначе ширина пользователя терялась бы после каждого сужения окна.
Во время перетаскивания разделителя пересчёт не вмешивается; состояние «узкого вида» обновляется
через 120 мс после того, как окно перестали тянуть (иначе перерисовка на каждый пиксель).
