### v1.2.311 — Доводка по ревью аватара веб-Telegram (устойчивость: свой профиль + запас попыток + лог)

Дата: 2026-08-19. Три правки по придирчивому ревью в [webAvatarScript.js](../src/utils/webAvatarScript.js) `__grabBig` (сам захват фото v1.2.309 подтверждён рабочим, это доводка устойчивости): **(#1)** раньше брался ПРОСТО крупнейший не-заглушка аватар — теоретически мог оказаться чужим, если крупнее своего. Теперь среди прошедших проверку кандидатов ПРЕДПОЧИТАЕТСЯ тот, что внутри контейнера Настроек/профиля (`ae.closest('[class*="settings" i], [class*="profile" i], .sidebar-header')` = точно «свой»); если такого нет — как раньше, крупнейший (безопасный fallback, текущее поведение не ломается). Победитель рисуется в канвас ОДИН раз в конце (а не `toDataURL` на каждого кандидата — меньше работы). **(#2)** медленный интернет: лимит попыток авто-Настроек 5→8, ретраев внутри одного захода 4→5 — больше шансов дождаться прогрузки фото, прежде чем сдаться на бледную запаску. **(#3)** «отравленная» (cross-origin) картинка раньше пропускалась МОЛЧА (`catch → continue`) — теперь пишет в журнал `grab|skip:<name>` (при будущем сбое видно причину). 🟢-находка (осиротевшие ключи `_crisp/_crisp3/_tries6` в localStorage от переименований) осознанно НЕ трогалась — мёртвый груз, безвредно. Проверки: линт EXIT 0, синтаксис инъекции OK (`new Function`), лимиты 584/584 (webAvatarScript 173 стр; renderer-бюджет 34555→34560 постоянно под код фикса), **vitest 2312/2312**. Остаточный риск: 🟡 если у аккаунта фото грузится дольше 8 попыток — останется запаска (крайне медленный канал). **Требует перезапуска + визуальной проверки.** Откат: `git checkout src/utils/webAvatarScript.js`.

### v1.2.309 — ФИКС (доводка): берём самый крупный НАСТОЯЩИЙ аватар среди всех, а не «просто самый большой»

Дата: 2026-08-19. Подсказка пользователя: при открытии профиля в Telegram фото пару секунд мутное/серое, потом чёткое (грузится ступенькой). Журнал v1.2.308 подтвердил: `gate|crisp=N|t=5` — сброс сработал, серую заглушку отвергали (не сохраняли junk), НО за 5 попыток настоящее фото так и не поймали и сдались (`sel=stored`). КОРЕНЬ: `__grabBig` брал ПРОСТО самый большой кружок ≥80px и проверял ТОЛЬКО его — а самым большим часто была серая заглушка загрузки → отвергали → blank, при этом настоящее фото (другой/такой же кружок) не рассматривали. Фикс: `__grabBig` теперь перебирает ВСЕ кандидаты ≥80px, каждый оценивает (яркость+детальность), пропускает заглушки (`mx-mn<18` ИЛИ `avg<100 И mx-mn<70`) и берёт самый крупный НАСТОЯЩИЙ; если все большие — заглушки → `blank` (ждём следующей попытки, ретраи из v1.2.308 дают ~9с). Плюс сброшен счётчик попыток (`__cc_tg_open_tries6`→`7`), т.к. в прошлой сессии он упёрся в 5. Диагностика `__measureCorners` оставлена для проверки (углы должны стать ~255/светлыми). Проверки: линт EXIT 0, синтаксис инъекции OK, лимиты 584/584 (webAvatarScript 190 стр). **Требует перезапуска + визуальной проверки** (серый/мутный → чёткое фото; журнал `auto|opened|grab=OK…` вместо `grab=blank`). Откат: `git checkout src/utils/webAvatarScript.js`.

### v1.2.308 — ФИКС: аватар веб-Telegram снимался как серая «заглушка загрузки» (отвергаем тёмное + ждём фото + сброс)

Дата: 2026-08-19. Диагностика v1.2.307 (`__measureCorners`) дала точный ответ: снятое чёткое фото = РОВНЫЙ ТЁМНО-СЕРЫЙ (`corners sz=100x100|TL=77,77,77|…|C=72,75,76`), т.е. `__grabBig` захватил СЕРЫЙ кружок-плейсхолдер Telegram (показывается, ПОКА реальное фото грузится), а не фото. Порог «пустое» (`mx-mn<18`) серый градиент-плейсхолдер проходил (разброс красного ≥18). Три осторожные правки в [webAvatarScript.js](../src/utils/webAvatarScript.js): (A) `__grabBig` теперь отвергает и ТЁМНОЕ МАЛОДЕТАЛЬНОЕ (`avg<100 И mx-mn<70`) — считает серый плейсхолдер `blank`; тёмное, но ДЕТАЛЬНОЕ фото (`mx-mn≥70`) проходит (не режем настоящие тёмные аватары); (B) авто-Настройки: даём фото прогрузиться — до 5 попыток `__grabBig` с паузой 1.6с (было 2), пауза после открытия 2.5→2.6с, всего ~9с в Настройках; (C) сброс залипшей серятины — ключ переименован `__cc_account_avatar_crisp`→`__cc_account_avatar_crisp2` (старый junk под прежним ключом игнорируется, гейт открывается → пересъёмка новым строгим `__grabBig`). Диагностика `__measureCorners` ОСТАВЛЕНА — по ней проверить, что углы стали белыми (~255); удалить после подтверждения. Проверки: линт EXIT 0, синтаксис инъекции OK (`new Function`), лимиты 584/584 (webAvatarScript 184 стр; renderer-бюджет временно 34575 под диагностику — вернуть 34550 после её удаления). Остаточный риск: 🟡 очень медленный интернет — фото может не успеть за 5 попыток → в этот заход останется бледная запаска, попробует снова через ~12с (не застрянет); 🟡 Настройки видны на экране ~9с при съёмке (было ~4.5с). **Требует перезапуска + визуальной проверки** (серый → белое фото с машинкой; в журнале `corners …|TL≈255…`). Откат: `git checkout src/utils/webAvatarScript.js`.

### v1.2.307 — ВРЕМЕННАЯ ДИАГНОСТИКА: замер цвета углов снятого аватара веб-Telegram

Дата: 2026-08-19. После фикса v1.2.306 значок веб-Telegram берёт настоящее фото (`sel=crisp-stored`), но пользователь видит СИНЕВАТЫЙ фон вместо белого (в Настройках фото — белый круг с синей машинкой). Гипотеза (совпадает с API-значком того же аккаунта): на 48px машинка «забивает» белый фон. Чтобы проверить ТОЧНО, в [webAvatarScript.js](../src/utils/webAvatarScript.js) добавлена временная `__measureCorners(dataUrl)`: грузит снятое чёткое фото, рисует 40×40, читает цвет 4 углов + центра + размер → в журнал (`[web-avatar-diag] … corners sz=…|TL=r,g,b|…|C=…`). Белые углы (≈255,255,255) = фото верное, просто мелкое (тогда фикс — показывать «целиком»/contain). Синие/тёмные углы = снялось «не то» (тогда правим ЧТО снимать). **Это НЕ фикс — сбор данных.** После диагноза удалить и вернуть renderer-бюджет 34565→34550. Проверки: линт EXIT 0, синтаксис инъекции OK. **Действие пользователя:** перезапустить dev → «📒 Логи ЦентрЧатов» → прислать строку `web-avatar-diag … corners …`.

### v1.2.306 — ФИКС: аватар веб-Telegram застревал на бледной запаске (разведены ключи хранилища + гейт по факту)

Дата: 2026-08-19. По журналу с машины пользователя (диагностика v1.2.305): веб-Telegram аккаунт отдавал `sel=stored` (бледная запаска из `stripped_thumb`), `gate|c=1` — авто-открытие Настроек отключено флагом, при этом DOM-дамп показал реальные `IMG.avatar-photo … nat160` (фото ЕСТЬ). КОРЕНЬ: чёткое фото (из Настроек, [webAvatarScript.js](../src/utils/webAvatarScript.js)) и бледная запаска ([constants.js:106](../src/constants.js), из `stripped_thumb`) писались в ОДИН ключ `localStorage['__cc_account_avatar']` → запаска ЗАТИРАЛА чёткое (последний писатель побеждает, факт уровня 1 MDN Web Storage), а флаг `__cc_tg_crisp3='1'` из прошлой сессии БЛОКИРОВАЛ переснятие. Фикс: (1) чёткое фото → ОТДЕЛЬНЫЙ ключ `__cc_account_avatar_crisp` (запаска в `__cc_account_avatar` его не трогает); (2) гейт авто-Настроек — по НАЛИЧИЮ чёткого ключа (`!crisp`), а не по залипавшему флагу `crisp3` (флаг удалён из кода, старое значение в хранилище игнорируется, безвредно); (3) порядок чтения Telegram: онскрин-большое → чёткое-из-ключа (`sel=crisp-stored`) → авто-Настройки → бледная запаска (`sel=stored`, быстрый fallback) → нацеленные селекторы. Диагностика v1.2.305 (`__ccDump`/`domDump`) УДАЛЕНА, renderer-бюджет возвращён 34565→34550. constants.js НЕ трогали (его запаска — законный быстрый fallback). Грабля записана в [mistakes/electron-core.md](mistakes/electron-core.md). Проверки: линт EXIT 0, синтаксис инъекции OK (`new Function`), лимиты 584/584, **vitest 2312/2312**. Остаточный риск: 🟡 добыча чёткого всё равно требует, чтобы авто-открытие Настроек сработало (кнопка «три полоски» + пункт «Настройки» + фото ≥80px в Настройках) — по журналу оно раньше срабатывало (флаг был выставлен), но гарантии на конкретной машине нет; 🟡 смена фото аккаунта обновится только при открытых Настройках (иначе кэш чёткого). **Требует перезапуска + визуальной проверки** (белый кружок → фото). Откат: `git checkout src/utils/webAvatarScript.js`.

### v1.2.305 — ВРЕМЕННАЯ ДИАГНОСТИКА: полный дамп DOM для поиска аватара веб-Telegram

Дата: 2026-08-19. Проблема: у веб-Telegram аккаунта на боковом значке показывается бледный/белый кружок вместо фото (крошечное превью `stripped_thumb` застряло, «чёткий» захват через авто-открытие Настроек не доходит). Чтобы НЕ гадать по селекторам, в [webAvatarScript.js](../src/utils/webAvatarScript.js) добавлена временная функция `__ccDump()`: обходит ВСЕ `img/canvas/[class*=avatar]` на странице Telegram, пишет размер+адрес+класс (от крупных к мелким, до 14 шт.) → уходит в журнал приложения вместе с результатом (`[web-avatar-diag] telegram: … DOM: …`) на «плохих» исходах (показан `stored`-блеклый или `none`). Заполняется `domDump` только для Telegram. Цель — по реальному DOM увидеть, где лежит фото аккаунта, и поправить захват прицельно. **Это НЕ фикс — сбор данных.** После анализа диагностику удалить и вернуть renderer-бюджет 34565→34550 ([fileSizeLimits.test.cjs](../src/__tests__/fileSizeLimits.test.cjs)). Проверки: линт EXIT 0, синтаксис инъекции OK (`new Function`), лимиты 584/584. **Действие пользователя:** перезапустить dev → открыть «📒 Логи ЦентрЧатов» → прислать строку `web-avatar-diag telegram … DOM: …`.
