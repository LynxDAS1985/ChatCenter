### v1.2.73 — Подсказка: фикс узкой вертикальной карточки (после скрытия/переноса панели)

Дата: 17 июля 2026. Кто нашёл: пользователь — перетащил панель, и подсказка стала всплывать узкой высокой полосой (текст по одному символу в столбик); до переноса было нормально.

Фикс ([dockPinState.js](../main/handlers/dockPinState.js)): в `showTooltip` ПЕРЕД отправкой данных окну возвращается просторный офскрин-бокс (`setBounds width:300`), поэтому карточка меряется по своей `max-width:258`, а не по 1px. Дальше `positionTooltipAndShow` ставит окно уже по правильному фактическому размеру.

### v1.2.69 — Док: hover-подсказка убрана (петля дёрга невозможна структурно) + дед-бэнд

Дата: 17 июля 2026. Свежий лог `[dock-bounds]` (16:39-40) показал: cooldown из v1.2.68 петлю НЕ убрал — `preview-grow`(h37→129)↔`preview-shrink`(h129→37) по-прежнему шли парами 2-3/с. `bottomMoved=false` везде (низ не двигается — привязка ок). Плюс `src=resize` с ползущим низом (`816→817→818`) и дрожанием x при тиках.

Проверка окна уведомлений (по требованию юзера «проблема была и с другими окнами»): в логе `[notif-window]` только `move`/`hide`, петли grow/shrink НЕТ. Ключ: окно уведомлений НЕ меняет размер при наведении. Значит структурная причина петли дока — именно ресайз окна на hover (под подсказку): рост окна под курсором → Windows шлёт ложные `mouseleave`/`mouseenter` → hide→shrink→show→grow → цикл. Cooldown это лишь глушил, но не всегда успевал.

Решение (как в окне уведомлений — не ресайзить на hover):
1. **Убрана всплывающая подсказка при наведении** ([pin-dock.js](../main/pin-dock.js)): удалены hover-listeners (`mouseenter`/`mouseleave`) и функция `showPreview`. Окно дока больше НЕ растёт на наведение → петля невозможна структурно (не заглушена, а исключена). Контент задачи открывается кликом (разворот карточки). `hidePreview` оставлена как безопасный no-op (вызовы на клике/меню/удалении не трогали).
2. **Дед-бэнд в `dock:resize`** ([dockPinHandlers.js](../main/handlers/dockPinHandlers.js)): при микро-изменении (Δширина≤6, Δвысота≤4, Δx≤6, Δy≤4) и видимом окне — `return` без `setBounds`. Гасит «медленный уход вниз»/дрожание от тиков таймера и мутаций.

Диагностический `[dock-bounds]` оставлен ещё на раунд: подтвердить, что строк `preview-grow/shrink` больше НЕТ вообще, а `src=resize` не идёт пачками.

Компромисс (честно): всплывающая подсказка-«краткое содержание» при наведении удалена — это цена за гарантированное отсутствие петли (полумеры не сработали). Если подсказка нужна — её можно вернуть отдельным окном-тултипом, которое НЕ ресайзит док (отдельная задача).

Проверки: `node --check` обоих, `npm run lint`, `npm run check-memory`. Визуально после ПОЛНОГО перезапуска: навести на вкладку — ничего не мигает, панель стоит; в логе нет `preview-grow/shrink`.

Откат: `git checkout -- main/pin-dock.js main/handlers/dockPinHandlers.js`.

### v1.2.67 — ДИАГНОСТИКА дёрга панели дока (временный лог)

Дата: 17 июля 2026. Причина: фиксы v1.2.62/64 (динамический рост + `position:fixed`) не убрали «дёрг» полоски дока при подсказке/меню; воспроизвести сам не могу (запуск приложения агенту запрещён). Чтобы не гадать — добавлен точный лог.

Что добавлено: в [dockPinHandlers.js](../main/handlers/dockPinHandlers.js) хелпер `logDockBounds(src, before, after)` пишет `[dock-bounds]` при КАЖДОМ `setBounds` окна дока — источник (`resize`/`preview-grow`/`preview-shrink`/`ctxmenu-grow`/`ctxmenu-shrink`), старые и новые `{x,y,w,h}`, и ключевое `bottom=y+h` + флаг `bottomMoved`. Если `bottomMoved=true` — низ окна двигается → полоска физически прыгает (значит рост окна не сохраняет низ). Если `bottomMoved=false`, а визуально всё равно дёргает — причина не в геометрии (native-repaint flash Win11 или другая цепочка).

Как снять диагноз (юзер): полностью перезапустить → навести на вкладку (спровоцировать дёрг) → в «📒 Логи ChatCenter» скопировать строки `[dock-bounds]` → прислать. По ним ставится точный диагноз.

Временно: удалить лог после нахождения причины (не горячий путь — только на resize/hover/menu).

### v1.2.65 — Закреплённое переживает перезапуск (баг персистентности)

Дата: 17 июля 2026. Кто нашёл: пользователь — закреплённые задачи не сохраняются после перезапуска.

Проверка перед правкой (может это уже есть): сохранение/загрузка закрепа **уже реализованы** (v0.72.1) — `savePinItems()` → `storage.set('pinItems')`, `loadPinItems()` при старте → `restorePin`. Значит функция есть, но не работает.

Корень (факт из данных): на диске `ЦентрЧатов/chatcenter.json` (живой, mtime сегодня) — `"pinItems": []`, хотя закреплённые есть на экране. Причина: обработчик `'closed'` окна закрепа делает `pinItems.delete(pinId)` + `savePinItems()` ([dockPinHandlers.js](../main/handlers/dockPinHandlers.js), [dockPinState.js](../main/handlers/dockPinState.js)). При ВЫХОДЕ из приложения Electron закрывает все окна закрепа → у каждого срабатывает `'closed'` → пины по одному удаляются из Map, а storage перезаписывается пустым списком. Итог: сохранять нечего при следующем старте. Персистентность сама себя стирала на выходе.

🥇 Electron: `app` эмитит `before-quit` ДО закрытия окон; окна затем шлют `'closed'`. Значит выход можно распознать флагом.

Фикс: флаг `isQuitting` по `app.on('before-quit')` (в `initDockPinSystem`), проброшен в `createDockPinState` как геттер. Оба `'closed'`-обработчика (создание в dockPinHandlers, восстановление в dockPinState) в начале: `if (isQuitting) return` — на выходе НЕ трогаем storage. Последнее нормальное сохранение (с пинами) остаётся и восстанавливается при старте.

Не затронуто: явное открепление (кнопка ✕ / `pin:unpin` / `dock:unpin`) идёт через `removePin`, который удаляет и сохраняет ДО закрытия окна; его `'closed'` уже был no-op (item удалён) — поведение сохранено.

Конфликты/граничные: `before-quit` фиксирует выход один раз; если пользователь отменит выход (в этом приложении не бывает) — флаг останется true (мелкий edge). На выходе таймеры не чистятся в guard — процесс всё равно завершается.

Проверки: `node --check` обоих файлов, `npm run lint`, `npm run check-memory`, тесты области.
