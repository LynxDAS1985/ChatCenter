# Архив changelog: v1.2.460 – v1.2.462

Вынесено из [`features.md`](../features.md) в v1.2.465, чтобы активный файл остался
в пределах лимита 100 КБ. Правила архива — в [`../README.md`](../README.md).

Темы этих версий:
- **v1.2.462** — МАКС: задвоенное имя отправителя ломало защиту от повторов (три карточки
  на одно сообщение); защита научилась писать в журнал и про ПРОПУСК, а не только про блокировку.
- **v1.2.461** — пустое сообщение Telegram перестало быть немым: вид попадает в журнал
  (`[tdlib-empty]`). ⚠️ Тема ПРОДОЛЖЕНА: запись сработала, вид назван (`messageUnsupported`),
  честная подпись сделана в v1.2.465 — см. активный `features.md`.
- **v1.2.460** — программа больше не выдаёт себя за продукт GitHub («Компания» в свойствах
  файла); разгрузка перед упором в планку строк.

⚠️ Действующие правила НЕ в архиве: ловушки — `mistakes/webview-injection.md`,
решения — ADR-057…ADR-060, отладка уведомлений — `notifications-debug.md`.

### v1.2.462 — 🔴 ЖАЛОБА «почему так много» (МАКС, три карточки на одно сообщение): задвоенное имя ломало защиту от повторов

**ЖАЛОБА** (2026-09-15, скриншот): три карточки уведомления подряд на ОДНО входящее в МАКС.

**КОРЕНЬ (🟢 доказан журналом `chatcenter.log` 17:13:44–45 + чтением кода)**. Журнал восстановил
всю секунду целиком — три карточки пришли ТРЕМЯ разными путями:
| id | Путь | Текст | Имя отправителя |
|---|---|---|---|
| 17 | `__CC_NOTIF__ src=max-sidebar` (список чатов) | `check.pdf` | `Бузов Алексей Николаевич` |
| 18 | запасной путь IPC (`__CC_NOTIF__ не пришёл за 500мс`) | `Новые сообщения … PDF check.pdf Скачать • 9.17 KB` | **`Бузов Алексей Николаевич      Бузов Алек…`** |
| 19 | `__CC_MSG__` → своё дообогащение через 1200мс | ТОТ ЖЕ текст, что у 18 | `Бузов Алексей Николаевич` |

**id=18 и id=19 — это ОДНО И ТО ЖЕ сообщение с одним и тем же текстом.** Отличалось только имя:
у 18 оно ЗАДВОЕНО. Имя входит в ключ сравнения повторов
([buildMessageDedupScope](../src/utils/messageProcessing.js)) → задвоенное = «другой человек» →
защита не сработала. В журнале за день задвоенное имя встречается **128 раз** — это не случайность.

**ОТКУДА ЗАДВОЕНИЕ**: имя активного чата собирает `getActiveChatSender`
([chatMetadata.js](../main/preloads/utils/chatMetadata.js)) из `.topbar .headerWrapper`. По правилу
MDN `Node.textContent` склеивает текст ВСЕХ вложенных узлов, а МАКС держит имя в разметке дважды
(видимая надпись + копия для программ чтения с экрана) и дописывает подпись времени. Отсюда
`«Имя      Имя Только что»`. Подпись времени МЕНЯЕТСЯ каждую минуту — второй источник рассинхрона.

**ЧТО СДЕЛАНО (один файл кода + один журнальный след)**
1. [cleanSenderStatus](../src/utils/messageProcessing.js) — единственное место, через которое имя
   проходит у ВСЕХ поставщиков до построения ключа сравнения. Добавлено: схлопывание подряд идущих
   пробелов, срез подписи времени в конце («Только что», «1 мин назад», «вчера», «12:30»),
   схлопывание ТОЧНОГО повтора имени целиком (`collapseDoubledName`).
2. [webviewHandleNewMessage.js](../src/utils/webviewHandleNewMessage.js) — защита от повторов теперь
   пишет в журнал и ПРОПУСК (`ПРОПУЩЕНО | scope=… key=… вМоменте=N`), а не только блокировку.
   Раньше при пропуске она молчала — разобрать жалобу было физически не по чему (пробел №2 из
   [notifications-debug.md](notifications-debug.md)).

🔴 **ПОЧЕМУ ЧИНИЛИ В ОБЩЕМ МЕСТЕ, А НЕ В СБОРЩИКЕ ИМЕНИ**: задвоить имя может ЛЮБОЙ поставщик
(у `max.hook.js` свой сбор через `.peer-title` — та же ловушка `textContent`). Правка в общей
чистке закрывает все пути разом; правка в одном сборщике закрыла бы один.

**ЧТО ОСОЗНАННО НЕ ТРОГАЛ (и почему это НЕ отговорка)**
- 🟡 **Третья карточка (id=17 против id=19) осталась необъяснённой.** По коду она БЫЛА ОБЯЗАНА

  правилом 3 фактов. Именно ради этого случая и добавлена запись о пропуске: следующее повторение
  покажет ключ обеих карточек и закроет вопрос. Записано в `code-todo.md` (TODO-41).
- 🟡 **Путь `max-sidebar` не участвует в уговоре «подожди обогащённое»** — правка изменила бы,
  КОГДА появляются уведомления, а проверить это без запуска приложения нельзя. Ждём данных из

### v1.2.461 — 🔴 ЖАЛОБА «пишет [медиа] вместо содержимого»: пустое сообщение перестало быть немым

**ЖАЛОБА** (2026-09-15, два скриншота): уведомление от канала Forbes Russia в 16:34 с текстом
`[медиа]`; в самом чате на этом месте — пузырь только с шапкой «Переслано от неизвестно» и БЕЗ
содержимого; в списке чатов у того же чата — «вложение».

**КОРЕНЬ (🟢 доказан чтением кода + журналом)**: пришёл вид сообщения, которого нет в разборе
[extractMediaInfo](../main/native/backends/tdlibMapperMedia.js) (там 16 знакомых видов, всё
остальное → `mediaType: null`). Текста у сообщения тоже не было. Показывать стало нечего.
Три разные надписи — потому что ответ спрашивают у ТРЁХ РАЗНЫХ мест, и у каждого своя заглушка:
| Где видно | Кто строит | Что подставляет, когда пусто |
|---|---|---|
| Уведомление | [nativeStoreIpc.js](../src/native/store/nativeStoreIpc.js) | `[медиа]` |
| Список чатов | [tdlibPreview.js](../main/native/backends/tdlibPreview.js) | `📎 вложение` |
| Сам чат | [MessageBubble.jsx](../src/native/components/MessageBubble.jsx) | НИЧЕГО — рисуются только знакомые виды |

**ДОКАЗАТЕЛЬСТВО ИЗ ЖУРНАЛА** (`chatcenter.log`, 2026-09-15):
```
16:34:38 [R:INFO] [native-notif] emit ... sender=Forbes Russia bodyLen=0
16:34:38 [INFO]  [NotifManager] show ... body=[медиа]
```
`bodyLen=0` — текста не было НА ВХОДЕ, а не «потерялся по дороге». Всего таких случаев в журнале
три: Forbes Russia ×2, HUAWEI | HarmonyOS ×1 — редко, но повторяется.

**ОПРОВЕРГНУТАЯ ВЕРСИЯ**: «текст есть, но теряется при разборе». Проверено чтением
[tdlibMapper.js](../main/native/backends/tdlibMapper.js): подпись берётся ОБЩИМ правилом
`content.text || content.caption` — для ЛЮБОГО вида. Значит подпись подхватилась бы даже у
незнакомого вида. Версия закрыта.

**ЭТО УЖЕ ТРЕТИЙ РАЗ**: та же беда была с анимированным эмодзи (v0.95.40) и со стикером/кубиком
(v0.95.47) — оба раза узнавали СЛУЧАЙНО, по скриншоту пользователя, потому что программа о
незнакомом виде нигде не писала. Комментарий об этом стоит прямо в `tdlibMapper.js`.

**ЧТО СДЕЛАНО (только запись, показ НЕ менялся)**
Новый `noteEmptyMessage` в [tdlibMapperMedia.js](../main/native/backends/tdlibMapperMedia.js):
когда сообщение вышло пустым (нет НИ текста, НИ вложения) — в журнал уходит строка
`[tdlib-empty] вид сообщения "<название>" — показывать нечего…`. Вызов — в
[tdlibMapper.js](../main/native/backends/tdlibMapper.js), сразу после разбора вложения, где
известны и текст, и вид.

🔴 **ПОЧЕМУ ПИШЕМ ПО ФАКТУ «ПУСТО», А НЕ ПО ФАКТУ «НЕЗНАКОМЫЙ ВИД»**: стикер, кубик и
анимированный эмодзи ТОЖЕ дают `mediaType: null`, но пустыми не выглядят — им подставляется
эмодзи вместо текста. Писали бы по «незнакомому виду» — журнал засорялся бы стикерами.

**СВЁРТКА**: каждый вид пишется ОДИН раз за запуск программы (приём проекта — так же свёрнут
шторм ошибок webview в v1.2.418). Поток одинаковых сообщений даёт одну строку, а не сотни.

**ПОКАЗ НЕ ТРОГАЛИ СОЗНАТЕЛЬНО**: пока не известно название вида, любая новая подпись может
оказаться неправдой. Возможны три разных исхода, и они требуют РАЗНОГО:
1. вид новее библиотеки (TDLib 1.8.64 отдаёт `messageUnsupported`) → содержимое показать
   НЕВОЗМОЖНО, нужна честная подпись «этот вид пока не поддерживается»;
2. вид библиотеке известен, а нам нет (в описаниях 1.8.64 есть репост истории, платный контент,
   розыгрыш, чек-лист) → можно и нужно показывать, надо добавить разбор;
3. сообщение действительно пустое (пересылка без содержимого) → нужна подпись, а не содержимое.

- 🔴 **Ловушка, которую вскрыл прогон «наоборот»**: свёртка «один раз на вид» живёт на ВЕСЬ прогон
  тестов, поэтому ловушка на вид, который встречается в тестах ВЫШЕ по файлу, молчит — запись уже
  съедена. Первые редакции ловушек (на стикере и на фото) поломку ПРОПУСКАЛИ. Переписаны на имена,

### v1.2.460 — «НАЙДЕНО, НЕ ТРОГАЛ» ЗАКРЫТО: программа выдавала себя за продукт GitHub + разгрузка перед упором в планку

перепроверена фактом — одна оказалась важнее, чем выглядела, одна закрылась сама собой.

**№1 🔴 (выглядело как 🟢): «Компания» в свойствах файла — «GitHub, Inc.»**
То есть собранная программа представлялась продуктом чужой фирмы. ПРИЧИНА найдена в исходнике
самого сборщика (`node_modules/app-builder-lib/out/appInfo.js`, версия 26.15.3):
```js
get companyName() { const author = ...metadata.author; return author == null ? null : author.name }
```
и `winPackager.js`: `if (appInfo.companyName != null) versionStrings.CompanyName = appInfo.companyName`.
В `package.json` поле `author` было **пустой строкой** → имя не подставлялось → в файле оставалось
значение Electron по умолчанию.
ФИКС: `"author": { "name": "ЦентрЧатов" }`.
ПРОВЕРЕНО ФАКТОМ (собрал распаковку, прочитал свойства файла):
```
CompanyName    : ЦентрЧатов          (было: GitHub, Inc.)
ProductName    : ЦентрЧатов
LegalCopyright : Copyright © 2026 ЦентрЧатов   (раньше падало на запасное значение)
```
СТРАЖ: [projectHealth.test.cjs](../src/__tests__/projectHealth.test.cjs) — поле `author.name` обязано
быть заполнено, с объяснением, откуда берётся «Компания».
