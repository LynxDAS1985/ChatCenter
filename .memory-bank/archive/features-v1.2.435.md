### v1.2.435 — Доводка по придирчивой самопроверке v1.2.434: журнал отказов по КАТЕГОРИЯМ, сбой впрыска не молчит, сторож реже, страж ссылок перестал быть слепым

**Контекст**: после подтверждения фикса v1.2.434 (см. запись ниже) работа была перепроверена «как чужая». Найдено 4 недочёта (🔴 не найдено), все закрыты здесь. Поведение для пользователя не меняется.

**1. 🟡 Бюджет журнала отказов уходил на одну причину** ([shared/browserBannerHider.js](../../shared/browserBannerHider.js))
- ЧТО: ключ дедупликации записей строился из полного текста причины, а причина содержит ЧИСЛО (`skip:текст-33546` ≠ `skip:текст-32771`). Теперь ключ = `tagName + причина БЕЗ цифр` (`v.replace(/[0-9]+/g, '')`), число остаётся в тексте записи. Плюс при исчерпании бюджета пишется строка `отказов больше не пишу (предел 8 видов)`.
- ЗАЧЕМ: в реальном журнале 2026-09-09 12:48:09 оказалось 8 строк отказа, и ВСЕ — `skip:текст-<разные числа>`. Бюджет `BANNER_LOG_LIMIT = 8` был израсходован одной причиной → более опасная (`skip:площадь-…`, т.е. попытка спрятать элемент во весь экран) в журнал уже не попала бы.
- КАК РАБОТАЕТ: проверено прогоном node — `skip:площадь-1000x800-из-1000x800` → ключ `skip:площадь-x-из-x`, `skip:не-отрисован` → без изменений; категории остаются различимыми. Крайние случаи: причин всего 5 видов, предел 8 — исчерпать нельзя штатно.
- КАК ПРОВЕРЕНО: новая ловушка в [browserBannerHider.vitest.js](../../src/__tests__/browserBannerHider.vitest.js) — три элемента с РАЗНОЙ длиной текста прогоняются через реальный впрыскиваемый скрипт (`new Function(buildBannerHiderScript())()`) с перехватом `console.log` → в журнале ровно ОДНА строка `НЕ прячу` (без фикса было бы три). 16/16.

**2. 🟡 Сбой впрыска глотался молча** ([src/utils/webviewSetup.js](../../src/utils/webviewSetup.js))
- ЧТО: было `el.executeJavaScript(buildBannerHiderScript()).catch(() => {})` — пустой обработчик. Стало: запись `WARN` через `window.api.send('app:log', …)` — `[banner-hider] впрыск НЕ прошёл для <id>: <причина>`.
- ЗАЧЕМ: факт уровня 1 (дока Electron 42, `webview-tag.executeJavaScript`: *«A promise that resolves with the result of the executed code or is rejected…»*) — путь отказа существует. Опасность именно теперь: отсутствие строк `banner` в журнале ошибочно читалось бы как «слов-триггеров не было», хотя это могло значить «скрипт вообще не запустился».
- КАК РАБОТАЕТ: `console.*` в renderer запрещён правилом проекта (в файл журнала не попадает) → использован принятый в этом же файле способ `app:log` (как на строке 158). Уровень WARN: подозрительно, но не фатально.
- КАК ПРОВЕРЕНО: линт 0; вызвать реальный отказ не на чем (нужен сайт, запрещающий выполнение скриптов) — **путь ошибки живьём не воспроизведён**, проверена только корректность кода и стиль записи.

**3. 🟡 Сторож пустого экрана фотографировал вкладку раз в 10 секунд бессрочно** ([src/utils/webviewBlackWatchdog.js](../../src/utils/webviewBlackWatchdog.js), [src/hooks/useWebViewLifecycle.js](../../src/hooks/useWebViewLifecycle.js))
- ЧТО: интервал вынесен в экспортируемую константу `WATCHDOG_INTERVAL_MS` и увеличен 10 000 → 60 000 мс. Число больше не «зашито» в хук.
- ЗАЧЕМ: сторож строился на теории «чёрный экран лечится принудительной перерисовкой», которая ОПРОВЕРГНУТА опытом (пинок применялся дважды и не помог, журнал 11:20:09 и 11:20:20), а настоящей причиной был наш впрыск (см. [[ADR-042]]). Каждая проверка — снимок всей вкладки (≈1100×768) + чтение пикселей, 6 раз в минуту.
- КАК РАБОТАЕТ: сторож ОСТАВЛЕН страховкой на другие возможные случаи, просто реже. Плата за это: если пустой экран возникнет по иной причине, узнаем через минуту вместо 10 секунд — принято осознанно. Откат: вернуть значение константы.
- КАК ПРОВЕРЕНО: ловушка в [webviewBlackWatchdog.vitest.js](../../src/__tests__/webviewBlackWatchdog.vitest.js) — `WATCHDOG_INTERVAL_MS >= 60000` (ловит возврат частого интервала). 19/19.

**4. 🟡 Страж битых ссылок был СЛЕПЫМ + 30 ссылок в features.md вели «в никуда»** ([src/__tests__/featuresReferences.test.cjs](../../src/__tests__/featuresReferences.test.cjs))

Проверено эмпирически: из `.memory-bank` файла `../../src/utils/webviewBlackWatchdog.js` не существует.
