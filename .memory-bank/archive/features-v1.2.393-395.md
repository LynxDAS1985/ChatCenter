# Архив features — v1.2.393–v1.2.395 (заставка первой загрузки чатов: старт саги + фиксы + разбор ВК)

Вынесено из features.md 2026-09-04 ради лимита 100 КБ. Активные записи — в features.md.

### v1.2.395 — Старт: убран «долгий пустой экран» — стартовая заставка «Загрузка…» держится до готовности (страховка 30с не гасит её раньше времени)

**ЗАЧЕМ**: жалоба — при запуске: заставка «Загрузка…» → потом ДОЛГО пустой тёмно-синий экран → потом грузится Макс и список. Хотелось: «Загрузка…» без долгой пустоты, затем заставка сборки чатов.

**КОРЕНЬ (по журналу + коду)**: стартовую заставку (`#cc-splash` в [index.html](index.html), встроена до React) в норме снимает `useAppBootstrap` при `appReady` ([useAppBootstrap.js:87](src/hooks/useAppBootstrap.js) → `window.__ccHideSplash`). НО страховка в [boot-probe.js](src/boot-probe.js) БЕЗУСЛОВНО убирала заставку через **30с**. В dev-режиме старт честно длится дольше: журнал 2026-09-04 — заставку сняла страховка на `+30004ms`, а `appReady` наступил на `+70809ms`, `NativeApp mounted` на `+127682ms` (сотни модулей грузятся по одному через dev-сервер, отдельные по 6-53с). Итог: заставку убрали на 30с → **~40-90с пустого экрана** до контента. Моя заставка сборки чатов (v1.2.393) при этом ОТРАБОТАЛА (журнал `[chatload] первая загрузка завершена: чатов=880`), просто показывалась ~2с ПОСЛЕ пустого экрана.

**ЧТО**:
1. [boot-probe.js](src/boot-probe.js) — страховка 30с теперь на 30с проверяет, ЖИВ ли `main.jsx` (он выставил `window.__ccHideSplash`): жив (медленный dev-старт) → заставку НЕ трогаем, её снимет `appReady`; ставим ДАЛЬНИЙ потолок 120с на случай реально зависшего `appReady`. Не запустился (битый бандл) → убираем, как раньше.
2. [appFallbacks.jsx](src/appFallbacks.jsx) `NativeAppFallback` — раньше чёрный div (между `appReady` и монтированием NativeApp ~57с в dev — пусто). Теперь та же подпись «Загрузка…» на тёмном фоне стартовой заставки → нет «пустоты» без индикатора.

**ИТОГ последовательности**: «Загрузка…» (до appReady) → «Загрузка…» (заглушка NativeApp до его монтирования) → заставка сборки чатов (v1.2.393) → список. Пустого экрана нет.

**ГРАНИЧНЫЕ / ОПАСНАЯ ЗОНА (boot)**: если `appReady` реально зависнет — заставку снимет дальний потолок 120с (не навсегда). Если `main.jsx` не запустится (битый бандл) — прежнее поведение (снять на 30с). Правки чисто ВИЗУАЛЬНЫЕ, на работу приложения (загрузку кода/данных) не влияют. **Длительность dev-старта НЕ уменьшилась** (127с — это медленная раздача модулей dev-сервером; в реальной сборке — секунды): фикс убирает ПУСТОТУ, а не ускоряет старт.

**УРОК**: страховочный таймер, гасящий индикатор загрузки, должен отличать «код не запустился» (гасить) от «код жив, но медленно грузится» (ждать) — иначе в медленной среде он срабатывает при НОРМАЛЬНОМ старте.

**КАК ПРОВЕРЕНО**: `node --check` boot-probe OK; `npm run lint` 0; `appStructure` 60/60, `rendererConsoleGuard` 0 нарушений, `startupDiagnostics` 4/4; `fileSizeLimits` 602/602; полный `vitest`. **Требует визуальной проверки** (перезапуск: «Загрузка…» держится без пустого экрана до появления списка) — boot-код автотестом не покрыть.

**ОТКАТ**: `git checkout src/boot-probe.js src/appFallbacks.jsx` + версия на 1.2.394.

### v1.2.394 — Заставка загрузки: 2 фикса по ревью (сохранение «итога» по завершению, а не по скрытию; клики при затухании) + логи

**ЗАЧЕМ**: придирчивое ревью заставки v1.2.393 нашло 2 своих (внесённых той же правкой) крайних бага.

**ФИКС #1 — «итог» (общее число чатов) сохранялся при ЛЮБОМ скрытии заставки, в т.ч. при поиске во время загрузки** → в `localStorage['cc_chat_total_hint']` попадало НЕПОЛНОЕ число (напр. 12 вместо 692), и следующий запуск показывал «из 12». КОРЕНЬ: сохранение висело в ветке скрытия эффекта показа ([ChatListLoadingSplash.jsx](src/native/components/ChatListLoadingSplash.jsx)), а заставка прячется по `show = chatsLoading && !search` — т.е. и при вводе в поиск. РЕШЕНИЕ: сохранение перенесено в ОТДЕЛЬНЫЙ эффект по зависимости `[loadDone]` — срабатывает ровно при ЗАВЕРШЕНИИ загрузки, независимо от скрытия. Новый проп `loadDone` (= `chatsFirstLoadDone`) проброшен InboxMode → сайдбар → заставка. `saveTotalHint` гардит `n>0` (0 чатов не перетрёт прошлый «итог»). Урок: overlay-состояние сохранять по СОБЫТИЮ завершения, а не по факту скрытия (у скрытия много причин).

**ФИКС #2 — заставка 0.42с при затухании перехватывала клики** по списку (нет `pointer-events`). РЕШЕНИЕ: `pointer-events: none` добавлен в `.native-chatload--leaving` ([styles-chatlist-loading.css](src/native/styles-chatlist-loading.css)) — во время финального затухания клики проходят к уже готовому списку. Во время самой загрузки (`show=true`) заставка клики по-прежнему блокирует (список не готов) — это правильно.

**ЛОГИ** (через `app:log`, не `console.*` — правило проекта): (1) INFO `[chatload] первая загрузка завершена: чатов=N, total сохранён/не сохранён` (в эффекте `loadDone` заставки); (2) WARN `[chatload] страховка 15с — loadChats не завершился, открываю список принудительно` (в `InboxMode.jsx`, когда сеть висит). Логи вне цикла (не в тик-таймере подписи) — без спама.

**КАК ПРОВЕРЕНО**: `npm run lint` 0; `ChatListLoadingSplash.vitest.jsx` 8/8 (в т.ч. +2 ловушки: «итог» пишется только при loadDone, а не при скрытии-из-за-поиска; `pointer-events:none` присутствует в CSS); `fileSizeLimits` 602/602 (InboxMode 1112/1116 — потолок поднят с обоснованием; бюджет renderer 35450); полный `vitest`. **Требует визуальной проверки** (клик в момент затухания срабатывает; поиск во время загрузки не портит «из N»).

### v1.2.393 — Нативный режим: живая заставка первой загрузки списка чатов (7 улучшений) + разбор значка ВК (без правки кода)

**ЗАЧЕМ**: жалоба — при первом запуске чаты появляются ПО ОДНОМУ (сначала Макс, потом остальные) — «мигает». Просьба: показать живую заставку, пока грузится, а список открыть РАЗОМ, готовым. Выбрана основа «аватарки по одному» + 7 улучшений (согласованы по макету-артефакту).

**ЧТО** (overlay-подход — список ПОД заставкой не размонтируется, как форум-панель в [InboxChatListSidebar.jsx:406](src/native/components/InboxChatListSidebar.jsx)):
- Новый компонент [ChatListLoadingSplash.jsx](src/native/components/ChatListLoadingSplash.jsx) + стили [styles-chatlist-loading.css](src/native/styles-chatlist-loading.css) (@import в `styles.css`). 7 улучшений: (1) подпись «Загружаем <имя>…» крутится по чатам; (2) настоящие буквы+цвета кружков (или фото-аватар из кэша); (3) галочка «готов» ✓; (4) живой счётчик «Загружено N» (реальный `store.chats.length`); (5) кольцо вокруг текущего; (6) плавный перелив цвета (hue); (7) плавный финал (fade → список).
- Флаг `chatsFirstLoadDone` (локальный `useState` в [InboxMode.jsx:118](src/native/modes/InboxMode.jsx)): ставится `true` по РЕЗОЛВУ `store.loadChats()` (полный батч), либо по страховке 15с (нет сети → не держим заставку вечно). Пробрасывается как `chatsLoading` в сайдбар; там заставка показывается поверх списка, пока флаг не выставлен, и не показывается при поиске.
- **Совет-улучшение «N из общего»**: заставка знает общее число чатов заранее — из прошлого запуска. Хранится в `localStorage['cc_chat_total_hint']` (записывается при завершении загрузки, читается на старте). Счётчик: «Загружено 5 из 692»; первый запуск (значения нет) → «Собираем чаты…». `try/catch` вокруг хранилища (приватный режим/запрет). Реализовано внутри `ChatListLoadingSplash.jsx` (InboxMode не рос).
- **Совет-страж (тест)**: новый [ChatListLoadingSplash.vitest.jsx](src/native/components/ChatListLoadingSplash.vitest.jsx) — поведение (show=true показывает имя+счётчик; show=false = нет в DOM; «из N» из localStorage; пустой store не падает) + source-guard проводки (сайдбар импортит+рендерит заставку; InboxMode держит `chatsFirstLoadDone` и передаёт `chatsLoading`). Падает, если заставку уберут → «мигание» не вернётся молча.

**ГРАНИЧНЫЕ СЛУЧАИ**: нет аккаунтов → заставки нет («Нет аккаунтов»); сеть висит → 15с-страховка открывает то, что успело подгрузиться; поиск во время загрузки → показываем результаты, не заставку; повторная загрузка при добавлении 2-го аккаунта → флаг остаётся true, заставка не всплывает снова (главная жалоба — первая загрузка — закрыта). `prefers-reduced-motion` → анимации выключаются.

**ВК (значок) — Вариант А выбран, КОД НЕ ПОНАДОБИЛСЯ (уже реализовано)**: пользователь выбрал «значок = число непрочитанных ЧАТОВ». Разбор по коду показал, что это УЖЕ действующее поведение — см. [[decisions]] ADR-039. Цепочка: `countUnreadVK` ([unreadCounters.js](main/preloads/utils/unreadCounters.js)) читает бейдж «Мессенджер N» (метод 2) → `sendToHost('unread-count', allTotal)` ([monitor.preload.cjs:258](main/preloads/monitor.preload.cjs)) → обработчик [webviewSetup.js:475-513](src/utils/webviewSetup.js) кладёт число в `unreadCounts[vk]` → значок рейла. Журнал подтвердил значение: `vk-src msgBadge=2 msgTx="Мессенджер2"` = 2 непрочитанных чата. Честный предел: VK НЕ отдаёт странице «сумму сообщений» (в заголовке окна числа нет — `titleN=нет`), только «число чатов». Моя временная запись `__CC_DIAG__unread_vk` в `countUnreadVK` в журнал НЕ попала (console.log из preload-утилиты не перехватывается webview-логгером — так же не видно давнего `unread_max`) → **откачена** как бесполезная. **Ожидает визуальной проверки**: пользователь смотрит, стоит ли «2» на значке ВК; если пусто — метод 2 не совпал с вёрсткой vk.ru (готовый мелкий фикс — расширить селектор до `a,[role=link]`, как в рабочем `vk-src`).
