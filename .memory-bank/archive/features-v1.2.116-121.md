### v1.2.121 — Telegram Web: НЕ показываем уведомления о сторис (историях)

Дата: 23 июля 2026. Фикс: из веб-Телеграма больше не приходит модалка «Х опубликовал(а) историю».

**Проблема (подтверждена логом).** Пользователь получал уведомление, что человек выложил историю. Лог `chatcenter.log` 18:38:21: `[Telegram] … __CC_NOTIF__ t="Яворенко Сергей Евге" b="опубликовал(а) историю"` → `[NotifManager] show … body=опубликовал(а) историю`. Корень: перехватчик `telegram.hook.js` передаёт ЛЮБОЕ уведомление сайта (`window.Notification` / `ServiceWorkerRegistration.showNotification`), а `_isSpam` знал «в сети/печатает/звонок», но НЕ знал про сторис.

**Что сделано.** В `_isSpam` (telegram.hook.js) добавлены УЗКИЕ маски `_story` (`^(опубликовал|добавил|разместил)\S*\s+(историю|видео\s+в\s+историю|фото\s+в\s+историю)$`) и `_storyEn` (`posted a story` / `added to their story` / `shared a story`). Гасится системная фраза ЦЕЛИКОМ (тело = только фраза, имя — в title), а НЕ слово «история» в произвольном тексте. Заблокированное логируется с reason `story` (наблюдаемость, не тихо).

**Крайние случаи / почему безопасно.** Прогон node из реального файла: «расскажи историю», «это долгая история», «опубликовал новую историю сегодня утром», «история болезни готова» — ПРОХОДЯТ; «опубликовал(а) историю», «опубликовала историю», «posted a story» — гасятся. Единственный теоретический ложный блок — если человек пришлёт сообщение ровно из фразы-штампа (практически невозможно, потеря 1 редкого сообщения некритична). Промах смещён в сторону «показать лишнее», не «спрятать нужное».

**Не затронуто.** Другие мессенджеры (у каждого свой `_isSpam`) и «родной» (TDLib) путь — НЕ трогали (шлёт ли native уведомления про сторис — не проверялось, отдельная задача). WhatsApp «статусы» — тоже отдельно.

**Проверка:** `node --check` OK; лимит `telegram.hook.js` 101/300; `notifHooks.test.cjs` 86/86; прогон правила (см. выше). **Ручная:** кто-то выкладывает историю в TG → модалки нет; обычные сообщения приходят как раньше.

Файл: `main/preloads/hooks/telegram.hook.js`. Откат: убрать строку `if (_story.test(t) || _storyEn.test(t)) return 'story'` (или `git revert`). Ловушка — [[webview-injection]].

### v1.2.120 — ВК/vk.ru: НЕ уведомляем о заглушённых чатах (🔕)

Дата: 23 июля 2026. Фикс: заглушённый в ВК чат больше не даёт нашу модалку.

**Метка «беззвучно» (по диагностике v1.2.116-118, строки `vkM`):** личный чат — `ConvoTitle__mutedIcon`; канал — `ChannelTitle__icon--muted` (обе содержат «muted»).

**Ловушка, которую нашли:** элемент-значок 🔕 присутствует в DOM и у ОБЫЧНЫХ (не заглушённых) чатов — у не-заглушённого «Сергей Пересыпкин» тоже был `ConvoTitle__mutedIcon`. Он просто СКРЫТ, когда чат не заглушён. → Проверять «есть элемент» НЕЛЬЗЯ (заглушит всё подряд), только «виден ли он».

**Что сделано.** Новая `_vkRowMuted(row)`: ищет `[class*="muted" i]`; считает чат замьюченным ТОЛЬКО если элемент реально виден (`display!=none`, `visibility!=hidden`, `opacity>=0.1`, есть размер / `getClientRects().length`). В `_scanVkList` замьюченные строки пропускаются (`muted++; continue`), в диаг-лог добавлен счётчик `muted=N` (для наблюдения — не заглушаем ли лишнее). Временный дамп `__CC_DIAG__vkM` (v1.2.116-118) удалён — файл `vk.hook.js` 298/300.

**Проверка:** `node --check` OK; лимит 298/300; следов диагностики 0. **Ручная (важно):** заглушённый чат (🔕) НЕ даёт модалку; НЕ заглушённые — дают (следить по логу `vk-list … muted=N`: если `muted` больше числа реально заглушённых видимых чатов — значит проверка видимости слишком широкая, сузить).

Файл: `main/preloads/hooks/vk.hook.js`. Откат: убрать строку `if (_vkRowMuted(...)) continue` (или `git revert`). Архитектура — [[decisions]] (ADR ВК vk.ru), ловушка — [[webview-injection]].

### v1.2.119 — ВК/vk.ru: текст уведомления берём целиком (не режем своей меркой)

Дата: 23 июля 2026. Фикс по просьбе пользователя: «не гадать с числом, брать сколько пришло».

**Проблема.** Уведомление ВК с длинным постом канала приходило обрезанным на полуслове (≈218 символов, скриншот «…А потом малыш внезапно»). Корень (по коду): `_vkRowText` резал результат `.slice(0, 220)` — своя произвольная мерка, а не «сколько дал ВК».

**Что сделано.** Убрана мерка 220: берётся ВЕСЬ текст из превью-элемента ВК; `.slice(0, 1000)` оставлен как **страховочный потолок** (не «мерка сообщения», а защита от гигантской простыни, чтобы карточка не разрослась). Для реальных превью = «сколько пришло, столько и показываем».

**Граница (не наша, важно понимать).** «Сколько пришло» = сколько ВК кладёт в СПИСОК чатов. Каналы — длинный кусок (теперь целиком). Личные чаты — ВК в списке даёт только короткое превью (1 строка); полный текст лежит лишь в ОТКРЫТОМ чате и без его открытия недоступен (отдельная большая работа). Карточка уведомления показ НЕ режет (collapsed — 1 строка `nowrap`, expanded — `max-height:300px` + прокрутка, [notification.css:166-190]).

**Проверка:** `node --check` OK; лимит `vk.hook.js` 300/300. **Ручная:** длинный пост канала в ВК → уведомление приходит целиком (или заметно длиннее прежнего).

Файл: `main/preloads/hooks/vk.hook.js`. Откат: вернуть `slice(0, 220)` (или `git revert`).

### v1.2.116 — ВК/vk.ru: диагностика признака «беззвучный чат» (🔕)

Дата: 23 июля 2026. Не фикс — сбор данных. Уведомление ВК подтверждено рабочим (чистый текст на скриншоте).

**Задача.** Не показывать уведомление для чата в беззвучном режиме ВК (у чата значок 🔕). Пример: чат «Доктор Владислав Ченчак» замьючен, но модалка пришла.

**Почему сразу не сделал.** Класс/атрибут значка «беззвучно» на vk.ru неизвестен. Гадать опасно: ошибочный признак может заглушить НУЖНЫЕ чаты (ложный пропуск хуже лишней модалки). Правило проекта — не менять по догадке.

**Что сделано.** Разовый дамп `__CC_DIAG__vkMute` в `_scanVkList` (`window.__ccVkMuteN < 3`): для 3 непрочитанных строк печатает имя + иконки/помеченные элементы (`svg,use,[aria-label],[title],[class*=mute|notif|icon]`) с tag/class/aria-label/title, короткими строками (лог режет ~60). По ним найду метку mute и добавлю пропуск замьюченных. Пропуск ПОКА НЕ включён.

**Проверка:** линт; лимит `vk.hook.js` ~296/300. **Действие пользователя:** ВК с записью диагностики → прислать строки `vkMute…` (замьюченный чат уже в списке).

Файл: `main/preloads/hooks/vk.hook.js`. Откат: удалить блок `__ccVkMuteN` (детект v1.2.115 не затронут).
