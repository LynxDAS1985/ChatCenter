### v1.2.372 — Окно сохраняет «на весь экран» при клике по уведомлению/закреплённой задаче

**ЗАЧЕМ**: жалоба — окно было развёрнуто на весь экран, клик по уведомлению (переход в чат) поднял окно в ОБЫЧНОМ размере. КОРЕНЬ (по коду): обработчики, поднимающие главное окно, звали `show()`+`focus()` без `restore()`. У СВЁРНУТОГО окна на Windows голый `show()`/`focus()` разворачивает его в обычный размер, теряя «на весь экран». Проектный образец рядом (`notif:mark-read`, [notifHandlers.js:71-73](main/handlers/notifHandlers.js)) уже использовал `restore()` при свёрнутом — а пути клика нет.

**ЧТО** (4 места, старый баг, не из правок этой сессии): [notifHandlers.js](main/handlers/notifHandlers.js) `notif:click` и `notif:ai-process`; [dockPinHandlers.js](main/handlers/dockPinHandlers.js) клик по доку и по закреплённой задаче — во всех перед `show()` добавлено `if (isMinimized()) restore()` (`restore()` возвращает окно из свёрнутого в ПРЕДЫДУЩЕЕ состояние, в т.ч. «на весь экран»). У видимого/скрытого окна maximize не трогается. В `notif:click` добавлена запись `[notif-click] window up: wasMin=… maximized=…` для подтверждения по журналу.

**КАК РАБОТАЕТ / крайние случаи**: окно видимо-развёрнуто → restore не зовём (guard `isMinimized`), остаётся развёрнутым; окно свёрнуто-развёрнуто → restore → развёрнуто; окно свёрнуто-обычное → restore → обычное (как было). **Откат**: `git checkout main/handlers/notifHandlers.js main/handlers/dockPinHandlers.js`.

**КАК ПРОВЕРЕНО**: `npm run lint` 0; `fileSizeLimits` 595/595; `mainRuntime` 108/108; `pinTooltip` 69/69. **Требует проверки**: свернуть развёрнутое окно → кликнуть уведомление/задачу → окно должно вернуться на весь экран; в журнале `[notif-click] … maximized=true`.
