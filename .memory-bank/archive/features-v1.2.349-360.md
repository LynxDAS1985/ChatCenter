### v1.2.360 — Окно надёжно открывается развёрнутым: maximize() перенесён на ready-to-show

**ЗАЧЕМ**: жалоба — после перезапуска окно открывалось НЕ на весь экран, хотя закрывали развёрнутым. Разбор по коду+журналу: приложение ПОМНИТ состояние (журнал `chatcenter.log` каждый старт: `restore maximized=true`), но `mainWindow.maximize()` вызывался СРАЗУ при создании окна ([windowManager.js:111](main/utils/windowManager.js)) — на Windows это ненадёжно (окно ещё не отрисовано) → команда не применялась. Память (сохранение/чтение флага + размера/позиции) работает корректно — ломалось только ПРИМЕНЕНИЕ разворота.

**ЧТО** (`main/utils/windowManager.js` 215/300): в существующий обработчик `once('ready-to-show')` добавлен повторный `maximize()` — если `plan.maximize` и окно ещё не развёрнуто. `ready-to-show` = окно отрисовано и готово к показу (офиц. Electron 42 docs) → maximize применяется надёжно. Вызов при создании оставлен как первая попытка (сработал — здесь no-op). Добавлена запись `[startup-window] post-ready maximize wanted=… isMaximized=…` для подтверждения по журналу. Сохранение (`saveBounds` на resize/move/maximize/close) и восстановление размера/позиции (`restorePlan`) НЕ трогались — они и так работают; «обычный» размер, испорченный прежней поломкой (записался почти-во-весь-экран), самоисправится, когда окно реально развернётся и пользователь его свернёт/изменит.

**КАК РАБОТАЕТ / крайние случаи**: окно уничтожено → guard `isDestroyed()`; уже развёрнуто → maximize() no-op; `plan.maximize=false` → не разворачиваем (оконный режим сохранён); два монитора → разворот на своём экране. В dev (медленная загрузка) окно секунду может быть не развёрнуто до `ready-to-show`, затем развернётся; в проде — быстро. **Откат**: `git checkout main/utils/windowManager.js`. **Ожидает проверки**: перезапуск → окно на весь экран + в журнале `post-ready maximize wanted=true isMaximized=true`.

### v1.2.350 — Виджет Ozon: тихо ловим ERR_ABORTED при переходе (убрана красная ошибка из журнала)

**ЗАЧЕМ**: по логу пользователя (13:13:36-37) — после кликов виджета `[ozon-widget] переход → "Вопросы"` затем `"Сообщения"` в журнал падал `[ERROR] ERR_ABORTED (-3) loading '.../app/messenger'` + `[R:ERROR] renderer-unhandled-rejection`. Страница при этом открывалась нормально (лог показывал успешную загрузку `.../app/messenger?group=customers_v2` секундой позже). КОРЕНЬ (по коду + логу): (1) Ozon ВСЕГДА переадресует `/app/messenger` → `/app/messenger?group=customers_v2`, из-за чего исходная навигация отменяется с `ERR_ABORTED (-3)` (норма для редиректа); (2) `webview.loadURL()` возвращает **Promise**, а `openSection` оборачивал его в СИНХРОННЫЙ `try/catch`, который async-отказ НЕ ловит → всплывал unhandled-rejection. Значит КАЖДЫЙ клик по «Сообщениям» давал красную ошибку.

**ЧТО** (`src/native/components/OzonQuickWidget.jsx`, 173/600): (1) к Promise от `loadURL` добавлен `.catch` — `ERR_ABORTED`/`-3` глотается тихо (это отмена из-за редиректа/быстрого повторного клика, не сбой); прочие ошибки → `app:log` уровня WARN. (2) URL раздела «Сообщения» сразу ведёт на `https://seller.ozon.ru/app/messenger?group=customers_v2` (куда Ozon и так редиректит) → отмены-переадресации больше нет вовсе. `match` остался `/app/messenger` (проверка по пути срабатывает и с query). Замок «только Покупатели» в `ozon.hook` (`_section`: `group=customers*`→buyers) с `customers_v2` совместим.

**КАК ПРОВЕРЕНО**: eslint 0; `fileSizeLimits` 593/593 (виджет 173/600, renderer 34888/34895); `rendererConsoleGuard` 0. **Требует перезапуска + визуальной проверки**: быстро переключать разделы виджетом — в журнале НЕ должно быть красного `ERR_ABORTED`/`renderer-unhandled-rejection`; раздел открывается как раньше. **Откат**: `git checkout src/native/components/OzonQuickWidget.jsx`.
