### v1.2.115 — ВК/vk.ru: 3 фикса по ревью (чистка времени, шторм на старте, дубль)

Дата: 23 июля 2026. Правки по итогам придирчивого ревью детекта ВК (v1.2.112–114). Каналы по решению пользователя оставлены (уведомляем обо всех, включая каналы-вещание).

**Фикс 1 — чистка времени больше не режет настоящий текст.** Регэксп `_vkRelTime` резал у ЛЮБОГО текста хвост «число + м/ч/с [назад]», из-за чего превью «буду через 5 минут» превращалось в «буду через». Заменён на две узкие маски: `_vkDateTail` (только после разделителя «·»: «· 36м», «· 2ч») и `_vkAgoTail` (только со словом «назад»: «36 минут назад») + `12:34`. Проверено прогоном (node): «буду через 5 минут», «скинь 10 м провода», «цена · 5кг» — НЕ режутся; «· 36м», «12:34», «36 минут назад» — режутся. [vk.hook.js:213-233](../main/preloads/hooks/vk.hook.js#L213).

**Фикс 2 — нет шторма старых уведомлений при медленной загрузке.** Базовая линия (`_vkPrevUnread`) снималась на любом первом замере, включая замер на ещё пустом списке; при догрузке все уже-непрочитанные улетали как «новые». Теперь базовая линия фиксируется ТОЛЬКО когда список непустой (`rows.length > 0`); пока пусто — режим «прайминга» продолжается, ничего не шлётся. [vk.hook.js:259-263](../main/preloads/hooks/vk.hook.js#L259).

**Фикс 3 — одно сообщение = одно уведомление за проход.** В одном скане две строки с одинаковым отпечатком «имя|текст» слались дважды. Добавлен набор `sent` — каждый отпечаток шлётся один раз за проход. [vk.hook.js:251-258](../main/preloads/hooks/vk.hook.js#L251).

**Не тронуто (осознанно):** повтор при прокрутке (не подтверждено, режет ли vk.ru DOM), мьют конкретного чата в ВК (нет данных о признаке mute), фильтр каналов (пользователь хочет все сообщения).

**Проверка:** `npm run lint` — чисто; `node src/__tests__/notifHooks.test.cjs` — 86/86; регэксп времени — прогон node (см. выше); лимит `vk.hook.js` 284/300. **Ручная (обязательно):** входящее в ВК → модалка с чистым текстом; проверить старт на медленной машине (нет пачки старых). Архитектура — [[decisions]] (ADR ВК vk.ru), грабли — [[webview-injection]].

Файл: `main/preloads/hooks/vk.hook.js`.

Откат: `git revert` коммита v1.2.115 (вернётся поведение v1.2.114).

### v1.2.114 — ВК/vk.ru: чистый текст уведомления по реальной структуре строки

Дата: 23 июля 2026. Финальная доводка текста ВК-уведомления (детект работал с v1.2.112).

**Структура строки списка ВК (по дампу `vkRow`, v1.2.113):**

- берётся спец-элемент превью: `[class*="PostPreview" i], [class*="preview" i], [class*="snippet" i], [class*="ListItem__text" i]`;

**Проверка:** линт; лимиты (`vk.hook.js` ~272/300). **Ручная (обязательно):** входящее в ВК от другого человека → модалка с ЧИСТЫМ текстом (превью без времени/счётчика).

**Открытый вопрос / где может «шуметь»:** строка в дампе была **каналом ВК** (URL `/im/channels/…`, `ChannelsListItem`). Детект сейчас ловит и каналы (broadcast-посты), не только личные чаты. Если это окажется шумно — исключим `ChannelsListItem` одной строкой (по решению пользователя).

### v1.2.113 — ВК/vk.ru: детект подтверждён логом + микро-диагностика структуры строки

Дата: 23 июля 2026. Промежуточный шаг: детект v1.2.112 подтверждён рабочим, доводим качество текста.

**Что показал лог (запуск v1.2.112, 15:23–15:27):**
- `vk-list reason=initial rows=166 unread=4 emitted=0` — базовая линия снята верно (старые непрочитанные не шлём).
- `vk-list reason=mutation rows=167 unread=4 emitted=2` — при новом сообщении отправлено 2 уведомления. **Детект работает end-to-end.**
- Имя отправителя вытащено верно: `t="Сергей Пересыпкин"`.
- НО текст: `"Все серьезно Фотография· 1мминуту назад"` = имя группы + превью «Фотография» + относительное время. Отсечён спам-фильтром приложения (`✗ Спам … минуту назад`) — правильно, но и правильное сообщение не показалось.

**Причина грязного текста.** Точные классы «имя/превью/время» внутри `.ConvoListItem` не были известны; угаданные превью-селекторы не совпали → `_vkRowText` взял «весь текст строки минус имя». Гадать дальше запрещено правилом → нужна реальная структура.

**Что сделано (v1.2.113).** В `_scanVkList` добавлен разовый (1 раз за сессию, флаг `window.__ccVkRowDumped`) дамп «начинки» непрочитанной строки: перебор ЛИСТОВЫХ элементов (`children.length===0`), каждый — короткой строкой `__CC_DIAG__vkRowN «ТЕГ.класс=текст»` (≤50 символов, влезает в журнал). По ним будут выбраны точные селекторы имени и превью, после чего текст станет чистым («Фотография» вместо мусора) и перестанет ложно ловиться спам-фильтром. Сам детект НЕ трогали — он рабочий; временный мусор пока безопасно гасит спам-фильтр.

**Проверка:** линт; лимиты (`vk.hook.js` ~276/300). **Действие пользователя:** написать в ВК (или дождаться нового сообщения) → прислать строки `vkRow0..N` из лога.

Файл: `main/preloads/hooks/vk.hook.js`.

Откат: удалить блок `__ccVkRowDumped` (или `git revert` коммита v1.2.113) — детект v1.2.112 останется рабочим.

### v1.2.112 — ВК/vk.ru: настоящий детект новых сообщений по списку чатов

Дата: 23 июля 2026. Настоящий фикс (не диагностика) — ВК на новом домене vk.ru снова даёт нашу модалку.

**Данные диагностики v1.2.111 (из лога, запуск 23.07 ~15:15):**
- `vkF1 ConvoListItem ConvoListItem--click` → строки списка чатов = `.ConvoListItem`.
- `vkB Convo=265 dlg=0 unread=2` → непрочитанные помечены классом с «unread» (в момент замера — 2).
- `vkA convo=0 cid=0 li=17` → ссылок `/im/convo` нет (строки не `<a>`); 17 видимых `role=listitem`.
- `vkTitle=Мессенджер` → счётчика «(N)» в заголовке вкладки нет → способ через заголовок отпал.
- `vk-toast scan=0` → всплывашки «Новое сообщение» на vk.ru нет (старый способ мёртв).
- Красная `[ERROR] Script failed to execute` = падение большого запасника `vkExecFallback` (vk.ru блокирует крупный впрыск) — ожидаемо, не поломка; наш preload-хук `vk.hook.js` грузится (в логе есть его строки).

**Что сделано.** В `vk.hook.js` добавлен наблюдатель за списком чатов (`MutationObserver`, тротлинг 500мс):
- строки — `[class*="ConvoListItem" i]`; непрочитанность — класс строки с «unread» ИЛИ вложенный `[class*="unread"|"counter"|"Badge"]`;
- имя отправителя — из `[class*="peer"|"title"|"name"]`/`b`/`strong`; текст — из `[class*="preview"|"snippet"|"subtitle"|"message"|"text"]` (фолбэк: строки текста минус имя), обрезаются время «12:34» и одинокий счётчик;
- аватар — `img[src^="http"]` (не emoji);
- эмит `__CC_NOTIF__ {t,b,i,g,src:'vk-list'}` → дальше общая логика мьюта/звука (как у всех мессенджеров).
- **Первый проход = базовая линия** (уже непрочитанные НЕ шлём), далее только новые отпечатки «имя|текст»; повтор того же сообщения не дублируется; сравнение с предыдущим набором непрочитанных (без TTL-переотправки).
- Переиспользованы `_isSpam` (отсев «Вы:», статусов, системных), `_cleanToastText`, `_hashToast`.
- Временная диагностика v1.2.110-111 (`vk-dom`/`vkTitle`/…) удалена. Toast-наблюдатель (для старого vk.com/edge-страниц) оставлен нетронутым.

**Проверка:** линт; лимиты (`vk.hook.js` ~253/300). **Ручная (обязательно):** написать в ВК с другого аккаунта → должна прийти наша модалка (не только звук ВК).

**Ограничения / где может сломаться:**
- Ловятся только ВИДИМЫЕ строки списка (vk.ru, вероятно, виртуализирует длинный список) — непрочитанный чат вне видимости можно пропустить. Так же было и в старом коде.
- Селектор «unread» — по данным замера (`unread=2`), но точную привязку значка к строке подтвердит только живой прогон. Если модалок 0 — в логе `__CC_DIAG__vk-list reason=initial ... unread=N` видно, находит ли наблюдатель непрочитанные (N>0 → селектор «unread» ок, доводим извлечение имени/текста; N=0 → уточняем признак непрочитанного).

Файл: `main/preloads/hooks/vk.hook.js`.

Откат: `git revert` коммита v1.2.112 (вернётся диагностика v1.2.111; детекта ВК не будет).

### v1.2.108 — Уведомления: время в строке источника, прижато вправо (единый формат)

Дата: 23 июля 2026. UI по просьбе пользователя (выбран вариант 2 из макета «5 расположений времени»).

**Проблема.** Время стояло в начале строки текста («10:38 Сейчас свяжусь…») — сливалось с сообщением.

**Решение.** Время (по настройке `showMessageTime`) переехало в строку источника под именем, ПРИЖАТО ВПРАВО: «Telegram · БНК                    10:38». Единый формат для ВСЕХ уведомлений — все карточки строятся общим `buildStackHeader` ([notification-helpers.js](../main/notification-helpers.js)).

**Как.** `buildStackHeader` получил параметр `time`. Строка `.notif-source` теперь флекс: `.notif-source-text` (источник, слева, с эллипсисом при длинном) + `.notif-source-time` (справа через `margin-left:auto`, `tabular-nums`). Из `.body-text` ([notification.js](../main/notification.js)) убран inline-span `.msg-time`; текст всегда кладётся в `.msg-text-content` (этот span нужен `toggleExpand` и обновлению подписи альбома).
