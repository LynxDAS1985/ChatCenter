### v1.2.415 — ФИКС ВК-значка: счётчик идёт в значок через console-канал (`__CC_UNREAD__`), а не через молчащий preload

**ЗАЧЕМ / КОРЕНЬ (доказан диагностикой v1.2.412-414 по логу)**: значок ВК в рейле был пуст, хотя ВК показывает «Мессенджер 2». Последовательно установлено: (1) тип определяется верно (`vk.ru`→'vk'); (2) обработчик значка показал бы число; (3) `countUnreadVK` результат не логировался — добавили диагностику; (4) канал `monitor-diag` из preload до файла НЕ доходит (0 строк `monitor-start`/`[MONITOR]`); (5) `[IPC-VK]` (гейт починен на URL, т.к. ВК — ПОЛЬЗОВАТЕЛЬСКИЙ мессенджер, id=`custom_…`) — ПУСТ даже после перезапуска, при живом console-канале (`vk-src`, `health` идут). **Вывод: ВК-webview НЕ шлёт хосту НИ ОДНОГО `ipc-message`** → `unread-count` от preload никогда не доходит до значка (у ВК как custom-мессенджера preload-путь молчит). А `vk.hook.js` счётчик для значка вообще не слал (только уведомления).

**ЧТО (надёжный фикс — по образцу Ozon, который тоже гонит счётчик через console)**:
1. [vk.hook.js](main/preloads/hooks/vk.hook.js) в `_scanVkList`: считает бейдж «Мессенджер N» (широкий `a,[role="link"]` + первое число — как рабочий `vk-src`) и шлёт `console.log('__CC_UNREAD__N')` ТОЛЬКО при изменении. **КАК РАБОТАЕТ / ОТКАТ**: значок ВК = бейдж «Мессенджер N» (число непрочитанных ЧАТОВ, ADR-039), обновляется при изменении. **КАК ПРОВЕРЕНО**: тест [consoleUnread.vitest.js](src/__tests__/consoleUnread.vitest.js) (4): `__CC_UNREAD__2`→2, `__CC_UNREAD__0`→0, то же значение→prev не пересоздаётся, мусор→не трогаем. Линт 0; лимиты 604/604 (webviewSetup вернулся к 604 после снятия диагностики `[IPC-VK]`). **Требует визуальной проверки** (перезапуск → значок ВК = число; в логе появится `__CC_UNREAD__N` от ВК).

**ОСТАЛОСЬ (тех-долг)**: (1) `countUnreadVK` (preload) для ВК теперь не используется — путь мёртв, но функция цела (правки v1.2.410/411 не мешают). ### v1.2.411 — ВК-счётчик: точность по ревью (не хватать чужое число из длинного превью — берём бейдж/короткую подпись)

**ЗАЧЕМ**: по ревью v1.2.410 (находка 🟡#2). Метод 2 в `countUnreadVK` брал «первое число из ВСЕГО текста» пункта «Мессенджер». `Node.textContent` (MDN) = склейка текста всех вложенных узлов → если в разметке РАНЬШЕ пункта попадётся строка-чат, где в превью случайно есть слово «мессенджер» и число (время/номер заказа), метод мог вернуть ЭТО чужое число.

**ЧТО** ([unreadCounters.js:142-158](main/preloads/utils/unreadCounters.js)): метод 2 переставлен на точность —
1. СНАЧАЛА точный источник: бейдж-счётчик ВНУТРИ пункта (`el.querySelector('[class*=ounter/badge/Badge]')`) → его число = счётчик непрочитанных;
2. Иначе — число из текста, но ТОЛЬКО если подпись КОРОТКАЯ (`text.length <= 30` = пункт меню, а не длинное превью чата).
Широкий поиск `a, [role="link"]` (фикс v1.2.410) сохранён.

**КАК РАБОТАЕТ / ОТКАТ**: значок ВК = число непрочитанных чатов из бейджа «Мессенджер» (ADR-039). Откат — `git checkout main/preloads/utils/unreadCounters.js`.

**КАК ПРОВЕРЕНО**: [unreadCountersVK.vitest.js](src/__tests__/unreadCountersVK.vitest.js) +2 (6 всего): длинное превью «…мессенджер…777…» СТОИТ РАНЬШЕ пункта → берётся пункт (1), не превью; вложенный бейдж `<span class="vkuiCounter">4</span>` → 4. Линт 0; полный vitest. **Требует визуальной проверки** (значок ВК = верное число).

**НЕ СДЕЛАНО ОСОЗНАННО (🟡#1 из ревью — нагрузка)**: широкий `querySelectorAll('a,[role=link]')` метода 2 выполняется на vk.ru часто (по мутациям DOM, ≤ раз/300мс). ### v1.2.410 — ВК: значок рейла был пуст при непрочитанном (vk.ru «Мессенджер» = [role="link"], узкий селектор не находил) + тест

**ЗАЧЕМ**: жалоба — в ВК висит непрочитанный чат (VK показывает «Мессенджер 1»), а значок ВК в боковом рейле приложения ПУСТОЙ.

**РАЗБОР (логи + код)**:
- Рабочий диагностический `vk-src` в [vk.hook.js:267-269](main/preloads/hooks/vk.hook.js) ищет «Мессенджер N» ШИРОКО — `document.querySelectorAll('a,[role="link"]')` — и стабильно находит: лог `vk-src msgBadge=1 msgTx="Мессенджер1"`.

На vk.ru пункт «Мессенджер» оформлен как `[role="link"]` ВНЕ nav → под узкий селектор не попадал → метод 2 возвращал 0 → значок пустой. **ЧТО**: в `countUnreadVK` метод 2 — селектор кандидатов расширен с узкого списка до `a, [role="link"]` (как в рабочем хуке). Текстовый фильтр `/мессенджер/i` оставлен → «Друзья»/«Игры» (фантомная 1) НЕ подхватываются. Методы 1 (title «(N)»), 3, 4 не тронуты.

**КАК РАБОТАЕТ / ОТКАТ**: значок ВК = число из бейджа «Мессенджер N» (число непрочитанных ЧАТОВ, ADR-039). Откат — `git checkout main/preloads/utils/unreadCounters.js`.

Линт 0; лимиты 604/604; полный vitest. **Требует визуальной проверки** (перезапуск → значок ВК показывает число непрочитанных чатов).
