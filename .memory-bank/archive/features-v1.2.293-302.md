### v1.2.297 — ФИКС: фото из уведомления не открывалось + окно не закрывалось (установленная версия)

Дата: 2026-08-19. Жалоба: в УСТАНОВЛЕННОЙ версии клик по фото в уведомлении → просмотрщик с битой картинкой «photo», и окно не закрывается (кнопки не реагируют). КОРЕНЬ (по коду, оба симптома — ОДНА причина): окно фото [photoViewerHandler.js:62](../src/../main/handlers/photoViewerHandler.js) — ЕДИНСТВЕННОЕ окно без `sandbox: false`. В prod preload собран как ESM (`out/preload/photoViewer.mjs`), а ESM-preload грузится ТОЛЬКО при `sandbox:false` (в песочнице preload обязан быть CommonJS — офиц. Electron). В dev preload = исходный `.cjs` → грузится и с песочницей → в dev работает, в установщике нет. Без preload нет `window.photo` → `onSetSrcs` не ставит `img.src` (виден alt «photo», «1/1» — заглушка в HTML), и `window.photo?.close()` — впустую. Фикс: добавлен `sandbox: false` в webPreferences окна фото (как у ВСЕХ прочих окон: notificationManager:119, windowManager:75, dockPin*, aiLogin, tray). `contextIsolation:true`/`nodeIntegration:false` сохранены. Гипотеза «сырой путь» из прошлого разбора отставлена — до подключения preload картинка вообще не ставилась. Проверки: линт 0, лимиты 584/584 (photoViewerHandler 104/500). **Требует УСТАНОВКИ нового установщика + проверки** (фото открывается, окно закрывается). Грабля: новые окна ВСЕГДА ставят `sandbox:false` (иначе ESM-preload отваливается в prod).
