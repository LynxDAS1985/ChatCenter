### v1.2.365 — Ozon Шаг 3А: КОРЕНЬ молчания найден — сторож не впрыскивался в фоновую страницу; впрыск через executeJavaScript

**ЗАЧЕМ / КОРЕНЬ (по коду + журналу)**: расширенная диагностика v1.2.364 (перезапуск 17:33) показала: фоновая страница проходит всю лесенку (создана→console→dom-ready→загрузилась URL=/app/reviews/questions), но НИ ОДНОГО сигнала хука (`ozon-list`/`ozon-q`). Значит `ozon.hook` НЕ впрыскивается. Причина (по коду): хук Ozon впрыскивается НЕ preload-ом (Ozon CSP блокирует preload-`<script>` — комментарий [monitor.preload.cjs:10](main/preloads/monitor.preload.cjs)), а через `executeJavaScript` из [webviewSetup.js:362-368](src/utils/webviewSetup.js) — но ТОЛЬКО для webview, зарегистрированных через `setWebviewRef`. Фоновая страница НЕ регистрируется (намеренно, чтобы не мешать health/refs) → executeJavaScript-фолбэк её не покрывал → сторож не запускался.

**ЧТО** (`src/utils/ozonBgWatcher.js`): в `dom-ready` фоновой страницы добавлен впрыск сторожа: `window.api.invoke('app:read-hook','ozon')` → `el.executeJavaScript(hookCode)` (в обход CSP, как для основной вкладки). Разово (флаг `_hookInjected`). Логи `[ozon-bg] сторож впрыснут` / `впрыск не удался`.

**КАК РАБОТАЕТ / крайние случаи**: `app:read-hook` пуст → WARN, не падаем; executeJavaScript упал → WARN; повторный dom-ready (SPA) → флаг + гвард `window.__ccOzonWatch` в самом хуке → двойного запуска нет. **Откат**: `git checkout src/utils/ozonBgWatcher.js`. **Требует перезапуска + проверки по журналу**: после впрыска должны пойти `[ozon-bg] ozon-q scan rows=N unans=M`. Если `rows=0`/`no-answers-col` → ОТДЕЛЬНАЯ гипотеза: SPA Ozon не рисует таблицу в СКРЫТОЙ вкладке (тогда — «будить» страницу).

**КАК ПРОВЕРЕНО**: `eslint` 0; `ozonBgWatcher.vitest.js` 8/8; `fileSizeLimits` 595/595; `rendererConsoleGuard` 0.
