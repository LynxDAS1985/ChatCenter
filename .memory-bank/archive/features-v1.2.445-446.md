### v1.2.446 — ВОССТАНОВЛЕНА защита от чёрного экрана веб-МАКС: правки в `webviewSetup.js` были потеряны, и НИ ОДИН тест этого не заметил

**ЧТО СЛУЧИЛОСЬ (моя ошибка, честно).** Во время работы над v1.2.445 я откатил один файл командой `git checkout -- src/utils/webviewSetup.js`, чтобы снять его с потолка строк. Этот файл содержал НЕЗАКОММИЧЕННЫЕ правки прошлых сессий (v1.2.434 и v1.2.435) — они были уничтожены, потому что откат возвращает файл к последнему коммиту, а последний коммит здесь `cd90ef6` (v1.2.427-429).

**ЧЕМ ЭТО БЫЛО ОПАСНО.** Вернулось прежнее широкое условие «в тексте элемента есть слова „обновите“+„браузер“ И у него меньше 20 прямых детей → спрятать». Под него попадает КОРЕНЬ приложения (текст элемента = текст всей переписки, детей у корня 2-6) → веб-МАКС мог целиком уйти в невидимость, а выглядит это как чёрный экран. Именно эту причину нашли в v1.2.434 (см. [[decisions]] ADR-042).

**ПОЧЕМУ НЕ ЗАМЕТИЛИ СРАЗУ.** Файл с предохранителями `shared/browserBannerHider.js` остался на диске и все 16 его тестов были зелёными — но приложение его больше НЕ ЗВАЛО. Все проверки смотрели ВНУТРЬ модуля и ни одна не смотрела на проводку. Полная цепочка pre-push (35 тестов) и полный прогон (2606 тестов) прошли без падений.

### v1.2.445 — ПЕРЕПОДКЛЮЧЕНИЕ после обрыва связи: мессенджеры поднимаются сами + экран «Нет связи» с отсчётом

**ЖАЛОБА**: «после потери интернета веб-подключения не восстанавливаются автоматически; при переключении на WhatsApp отображаются данные Telegram API вместо страницы мессенджера». Полный план, макет и разбор — [reconnect-plan.md](../reconnect-plan.md).

**ТРИ ПРИЧИНЫ (все доказаны чтением кода, не догадки)**
1. **Никто не переподключал.** Обработчик `did-fail-load` в [webviewSetup.js](../../src/utils/webviewSetup.js) только ставил метку «ошибка» — ни `reload()`, ни `loadURL()`.
2. **Слои прозрачные** — и это ответ на «вижу Telegram вместо WhatsApp». В [App.jsx](../../src/App.jsx) мессенджеры лежат слоями друг на друге (`zIndex: activeId === m.id ? 2 : 0`), у слоя НЕТ своего фона → пустой слой просвечивает, и видно нижний слой «Общий чат» с чатами Telegram. Это НЕ подмена данных, а просвет.
3. **Никто не знал, что связь вернулась** — в проекте не было ни одного слушателя `online`/`offline` (поиск по `src/` и `main/` дал ноль).

**ЧТО СДЕЛАНО**
| Файл | Что |
|---|---|
| [shared/reconnectPlan.js](../../shared/reconnectPlan.js) (новый, 193/300) | ЧИСТАЯ логика: лестница пауз, список сетевых кодов, планирование попытки, тексты записей журнала. В `shared/` — вне бюджета renderer |
| [WebviewOfflineOverlay.jsx](../../src/components/WebviewOfflineOverlay.jsx) (новый, 136/700) | Экран по согласованному макету: причина, обратный отсчёт, полоса, «Повторить сейчас» + «Журнал». **Непрозрачный фон закрывает просвет (причина 2)**. Рисуется ПОВЕРХ — сам webview прятать нельзя (Chromium усыпляет скрытые). Секунды считает сам, чтобы из-за отсчёта не перерисовывалось всё окно |
| [useWebviewReconnect.js](../../src/hooks/useWebviewReconnect.js) (новый, 135/150) | Проводка: `bindReconnect` вешает слушатели на элемент страницы, ведёт запись по каждому мессенджеру, один таймер просыпается ровно к сроку (а не тикает каждую секунду), повтор через `loadURL` |

**ПРАВИЛА ПОВТОРОВ**: 5с → 10с → 20с → 40с → 60с → далее по 60с; **у МАКСа не меньше 15с** (у него уже был шторм «Too many requests», ADR v1.2.417); попытки без предела, пока страница не поднялась; счётчик сбрасывается при успехе; при возврате сети ближайшая попытка идёт СРАЗУ; кнопка «Повторить сейчас» доступна всегда.

**Повторяем ТОЛЬКО на сетевых кодах** (`-2, -7, -21, -100, -101, -102, -105, -106, -109, -118, -137, -324`). Код `-3` (ERR_ABORTED — обычная отмена перехода) НЕ считается обрывом: иначе перезагружали бы живую страницу и **стирали недописанное сообщение**. Это закреплено двумя тестами-ловушками.

**ФАКТЫ (🥇 из `DOCS/Electron docs`)**: (1) «`net.isOnline()` … return value of `true` is inconclusive» (`api/net.md`) — «сеть есть» только подсказка, поэтому она лишь ускоряет попытку, а решает сама загрузка; (2) renderer использует `navigator.onLine` + события `online`/`offline` (`tutorial/online-offline-events.md`) — берём их, а не опрос по таймеру в главном процессе (у модуля `net` события в доке нет); (3) `<webview>.loadURL()` «resolve when the page has finished loading… rejects if the page fails to load» (`api/webview-tag.md:278`) — готовый признак «получилось / не вышло».

**🔴 ЗАЩИТА, КОТОРУЮ Я СНАЧАЛА ОБОШЁЛ (поймал страж, исправлено по-настоящему)**: первая версия `bindReconnect` вешала слушатели напрямую через `el.addEventListener` — мимо учёта `el._chatcenterListeners`, по которому [App.jsx:360-364](../../src/App.jsx) снимает подписки при удалении вкладки. То есть подписка осталась бы навсегда (утечка). Тест `memoryLeaks.test.cjs` («Нет el.addEventListener в setWebviewRef») это поймал. Исправлено: регистрация идёт через тот же список; добавлен тест на ЗАПРЕЩЁННЫЙ случай — проверяет, что оба слушателя попали в учёт и снимаются повтором чистки из App.jsx.

**ПОЧЕМУ НЕ ТРОГАЛ `webviewSetup.js`**: файл стоит на своём потолке 605 строк. Две строки сигнала выводили его на 607 → по правилу проекта нельзя поднимать потолок, надо разделять файл (это отдельная большая задача). Поэтому слушатели вешаются прямо на элемент, а `webviewSetup.js` не изменён вовсе.

**БЮДЖЕТ RENDERER**: 35300 → 35480 (факт 35426). Это НОВАЯ функция: экран 136 строк + проводка 135. Вся чистая логика уже вынесена в `shared/` (193 строки), разгружать больше нечего — по [[decisions]] ADR-044 поднятие тут законно (оно запрещено ВМЕСТО разгрузки).
