#### Что сделано (5 частей)

**1. «Пульс интернета»** — [netPulseHandlers.js](../main/handlers/netPulseHandlers.js) (обвязка Electron) +
[shared/netPulsePlan.js](../shared/netPulsePlan.js) (чистая логика). Главный процесс сам делает крошечный запрос
(`net.fetch` — по документации Electron идёт через сетевой стек Chrome) к трём служебным адресам проверки связи
(`msftconnecttest` — тем же адресом Windows проверяет интернет; `gstatic/generate_204`; `yandex.ru/favicon.ico`): любой
HTTP-ответ = интернет есть. Раз в 60 с в покое, раз в 15 с когда интернета нет ИЛИ окно сообщило, что мессенджеры ждут
повтора; немедленно при пробуждении компьютера / разблокировке экрана (`powerMonitor`) и по просьбе окна (кнопка
«Повторить сейчас»). В журнал — только **переходы**: `[net-pulse] интернет ПРОПАЛ …` / `ПОЯВИЛСЯ через N с (ответил host)`;
пока нет — напоминание раз в 5 мин. Каналы: main→окно `net:pulse`; окно→main `net:pulse-state` (invoke),
`net:pulse-now`, `net:pulse-waiting`. Выключатель: `settings.netPulse === false` (без интерфейса — аварийный рычаг).

**2. Пульс командует.** В окне ([useOpenPageWatch.js](../src/hooks/useOpenPageWatch.js) → `applyPulse`) вердикт кладётся в
`window.__ccNetOnline` и превращается в СТАНДАРТНОЕ событие окна `online`/`offline` — существующие слушатели
(`useWebviewReconnect`: все ожидающие пробуют СРАЗУ; `NativeConnectionStrip`: полоса «нет связи») оживают без переделки.
Главный процесс на «появился» зовёт TDLib `setNetworkType(networkTypeOther)` для всех аккаунтов
([tdlibBackendHelpers.js](../main/native/backends/tdlibBackendHelpers.js) `networkChangedRaw`; `networkTypeNone` не шлём никогда —
иначе сами отключили бы TDLib по ложному пульсу).

**3. Открытая страница под присмотром** — [shared/openPageWatch.js](../shared/openPageWatch.js) (правило) + хук выше. Исход
КАЖДОЙ пробы здоровья идёт в `onProbeOutcome`: 1-й провал → наблюдаем (мессенджеры переподключаются сами); 2-й подряд при живом
интернете → «страница зависла» → механизму повторов (перезагрузка по лестнице 5 с…); 2-й при мёртвом пульсе → экран «Нет
интернета», **страницу не трогаем**. Сама попытка вынесена в [shared/reconnectAttempt.js](../shared/reconnectAttempt.js): при
мёртвом пульсе `loadURL` НЕ зовётся (перезагрузка стирает недописанное); запись от пробы перед перезагрузкой **спрашивает
страницу** (`quickProbe`, тот же скрипт, что у панели связи) — ожила сама → экран снимается **без перезагрузки**.

**4. Различаем беды.** Экран «Нет связи» ([reconnectTexts.js](../shared/reconnectTexts.js) `reasonTitle`): «Нет интернета» /
«Сайт X недоступен — интернет есть, не отвечает сам сайт» / «X: страница не отвечает». После **10** неудач при ПОДТВЕРЖДЁННОМ
пульсом интернете пауза — 5 минут (`LONG_FAIL_ATTEMPTS`/`LONG_FAIL_PAUSE_MS`); эхо страницы-ошибки в журнал с 3-й попытки —

Зачем: при «не закрывать сами» карточки копятся, закрывать можно было только по одной (смежный пункт дела

Как устроено (по образцу `notificationNewPill.js`, `notification.js` НЕ тронут — он 719/730):
- кнопка живёт в `body`, **не в `#container`** — дети контейнера считаются карточками (линейка, снимок DOM, сверка
  `items↔containerChildren`), чужой элемент там сломал бы инварианты;
- при **≥2** карточках контейнер получает класс `has-toolbar` (`padding-top: 32px` = 4 обычных + 28 под полосу), кнопка —
  `position:fixed` в освободившейся полосе, чтобы **не накрывать крестик первой карточки**;

  28 — иначе окно было бы ниже содержимого на полосу; **без карточек полосу не считает** — «пусто» остаётся нулём (иначе
  пустое окно не пряталось бы: `computeRendererPure` смотрит на `visibleHeight===0`);
- нажатие = **нажать крестик каждой карточки** (`.close-btn.click()`): тот же путь, что у человека, со всеми записями в
  журнал (`close-click`, `dismiss start …`) и той же анимацией — ничего нового про закрытие не изобретаем;

  добавления карточки, класс должен стоять раньше. Журнал: `close-all: ready / shown count=N / hidden / click: закрываю N…`.
