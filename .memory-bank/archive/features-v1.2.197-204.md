### v1.2.204 — Окно фото: кнопки в шапке + вставка ещё фото Ctrl+V + свободнее двигать при зуме

Дата: 2026-08-06. По жалобам: (1) кнопки должны быть вверху у «Отправить фото»; (2) нельзя вставить второе фото через буфер; (3) при увеличении не даёт доехать до края.

**ЧТО и ЗАЧЕМ ([PhotoSendModal.jsx](../src/native/components/PhotoSendModal.jsx)):**
- **Кнопки зума/поворота — в ШАПКУ** (одна строка с заголовком «Отправить фото»), отдельная полоса убрана. Компактнее, не над фото.
- **Вставка ещё фото через Ctrl+V при открытом окне.** Раньше обработчик вставки висел на главном поле ввода ([useDropAndPaste.js](../src/native/hooks/useDropAndPaste.js) `onPaste`), а оно СКРЫТО под окном → Ctrl+V не работал. Теперь окно само слушает `paste` на window (MDN `ClipboardEvent.clipboardData.items` → `getAsFile`) и добавляет картинку через `onAdd` → она встаёт в ленту миниатюр.
- **Свободнее двигать при зуме (#3).** КОРЕНЬ: кламп сдвига был «cover» (`maxX=(contentW−containerW)/2`, [imageZoomPan.js](../src/native/utils/imageZoomPan.js)) — на «залетербоксенной» оси при среднем зуме `maxX=0` (двигать нельзя), по увеличенной оси край доходил лишь впритык. Добавлен режим `loose` в `clampOffset` (перетяг: `maxX≈contentW/2` — край фото можно вытянуть до середины окна, и на неполной по оси стороне тоже двигать); `clampT` при 100% держит по центру. Кламп по умолчанию (`loose=false`) НЕ изменён — старые тесты целы.

**КАК РАБОТАЕТ / крайние случаи:** пустой буфер / не-картинка → вставка игнор; при 100% сдвиг = 0 (по центру); отправка/поворот не тронуты. Откат: `git checkout -- src/native/components/PhotoSendModal.jsx src/native/utils/imageZoomPan.js` + удалить новый тест `loose` + версия на 1.2.203.

**КАК ПРОВЕРЕНО:** линт 0; тесты `imageZoomPan` 19 (+1 loose), `PhotoSendModal` 10, суммарно 83/83. **Требует визуальной проверки (dev, перезапуск):** кнопки в шапке; Ctrl+V добавляет второе фото в ленту; при зуме можно дотянуть край фото до середины окна и подвигать неполную сторону.

Дата: 2026-08-06. Жалоба: после перезапуска окно не запоминает размер/положение.

**КОРЕНЬ (по коду + реальным данным).** Сохранение размеров РАБОТАЛО ([windowManager.js](../main/utils/windowManager.js) `saveBounds` на `resize`/`move`, запись сразу на диск, `storage.js` `fs.writeFileSync`), но хранился ТОЛЬКО прямоугольник `getBounds()`, БЕЗ состояния «развёрнуто». Проверка живого файла настроек (`%APPDATA%/ЦентрЧатов/chatcenter.json`, изменён в момент запуска) показала `windowBounds: {x:-7,y:-7,width:1541,height:821}` — это метрики РАЗВЁРНУТОГО окна Windows (невидимые рамки −7px). При старте окно создавалось этих размеров, но `maximize()` не вызывался → открывалось большим и съехавшим, но НЕ развёрнутым. Кода про `isMaximized`/`maximize` не было вообще (grep по `main.js`+`windowManager.js` — 0 совпадений). Вторая папка `%APPDATA%/chat-center/` — мёртвая (март, 3 ключа), активна `ЦентрЧатов` (productName).

**Фикс (3 части, [windowManager.js](../main/utils/windowManager.js)):**
1. **Сохранение:** `saveBounds` теперь пишет `{ ...rect, isMaximized }`, где при развёрнутом окне `rect = getNormalBounds()` (обычный размер до разворота, официальное Electron API), иначе `getBounds()`. Добавлены слушатели `maximize`/`unmaximize`.
2. **Восстановление:** после создания окна, если `bounds.isMaximized` — `mainWindow.maximize()` (до показа, без мигания).
3. **Защита от ухода за экран:** `isBoundsVisible(bounds)` через `screen.getAllDisplays()` — если сохранённая позиция не пересекается ни с одним видимым дисплеем (отключили монитор/сменили разрешение), `x/y` не задаются → окно по центру, не «пропадает».

**КАК РАБОТАЕТ / крайние случаи:** первый запуск (нет `x/y`) → `isBoundsVisible=false` → центр (как было). Свёрнуто в трей → последний `saveBounds` уже на диске. Полноэкранный режим F11 (`isFullScreen`) НЕ сохраняется намеренно (чтобы не открывать приложение в фуллскрине неожиданно). Имя папки настроек НЕ трогали (переименование потеряло бы входы в Telegram). Откат: `git checkout -- main/utils/windowManager.js` + версия на 1.2.199.

**КАК ПРОВЕРЕНО:** `node --check` OK; линт 0; `mainRuntime` 101/101; `mainImports` parse OK. **Требует визуальной проверки (перезапуск):** развернуть окно → закрыть → открыть = сразу развёрнуто; окно своего размера → тот же размер/место.
