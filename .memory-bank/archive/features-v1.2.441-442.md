### v1.2.441 — ПЛАН ИСПРАВЛЕНИЯ по ревью v1.2.440: кнопка «Обновить фото» теперь видна на значке + неудача не теряется + убрана ЦИФРА из ключа записи журнала

**КОНТЕКСТ**: по просьбе пользователя реализован план исправления из придирчивой самопроверки v1.2.440 (пункты №1–№3; №4 сознательно не делался, см. ниже) + добавлены новые записи в журнал.

**ЧТО СДЕЛАНО**

**№1 — команда «Обновить фото аккаунта» теперь ВИДНА на значке.** Проблема (найдена чтением кода): пункт меню чистил служебные ключи в хранилище страницы мессенджера, но состояние значков менялось ТОЛЬКО при появлении нового фото ([useWebAccountAvatars.js](../../src/hooks/useWebAccountAvatars.js)), а ветка «фото не нашлось» состояние не трогала → на значке оставалось СТАРОЕ фото, и команда выглядела нерабочей (у МАКС это гарантированно: его фото видно лишь при открытых Настройках). Решение: [useTabContextMenu.js](../../src/hooks/useTabContextMenu.js) после УДАЧНОЙ чистки ключей шлёт событие `cc-avatar-reset` (`window.dispatchEvent(new CustomEvent(...))`), сборщик его слушает и применяет `applyAvatarReset` — убирает фото из состояния (значок возвращается к логотипу: [RailWebIcon.jsx:65](../../src/native/components/RailWebIcon.jsx#L65) рисует логотип, когда фото нет), снимает гейты журнала и забывает «последнее отданное фото». В ветке ОШИБКИ сброса значок НЕ трогается (закреплено тестом).

**№2 — неудача «НЕТ фото» больше не теряется.** Было: запись гейтилась по одному `id` → писалась один раз за запуск. После сброса фото повторная неудача (именно её и надо разбирать) в журнал уже не попадала. Стало: ключ несёт СОСТОЯНИЕ (`id | где искали | причина | ошибка`) — одинаковая неудача пишется один раз, ДРУГАЯ причина пишется снова.

**№3 — из ключа записи убраны ЦИФРЫ.** В поле `sel` зашит размер снимка (`'onscreen-big-' + big.sz`, [webAvatarScript.js](../../src/utils/webAvatarScript.js)) → смена размера на один символ давала НОВЫЙ ключ: повтор в журнале + бесконечный рост набора ключей. Это ТОТ ЖЕ класс ошибки, что чинили у Озона в v1.2.435 (`shared/browserBannerHider.js`: `v.replace(/[0-9]+/g,'')`). Теперь цифры чистятся в переменной части ключа, а в самом `id` СОХРАНЯЮТСЯ (иначе `custom_111` и `custom_222` слились бы в один ключ — отдельная тест-ловушка).
