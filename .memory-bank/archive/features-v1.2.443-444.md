**№2 🔴 Иконка в панели задач была бы серым пятном.**
Корень (🥇 по коду electron-builder 26.15.3, `app-builder-lib/out/util/iconConverter.js`): если дать ему PNG, он делает `.ico` **уменьшением** этой картинки. Замер: уменьшение 512→16 оставляет **1 белый пиксель вместо 41** (сравнил с нарисованным сразу 16 px, обе картинки смотрел увеличенными в 14 раз). Отдельно нарисованные мелкие размеры (`PNG/chatcenter-icon-16.png`) при этом не использовались НИКЕМ.
ФИКС: собираем `.ico` сами — [shared/appIconMark.js](../../shared/appIconMark.js) `buildICO()` (259/300) кладёт внутрь **6 картинок 256/128/64/48/32/16, каждая НАРИСОВАНА под свой размер** (у мелких линия толще). `build.win.icon` переведён с `build/icon.png` на `build/icon.ico`.
Почему это работает (🥇 тот же файл, строки 190-203): «If source already has the target extension … return it directly» — готовый `.ico` electron-builder **не перекодирует**, только читает заголовок и требует максимальный размер ≥256. Проверено его же порядком чтения: `картинок внутри 6, максимальный размер 256` ✅.
Формат `.ico` (спецификация Microsoft): заголовок 6 байт (0,0 | тип=1 | число картинок) + по 16 байт на картинку (ширина/высота, где 0 = 256; слоёв=1; бит=32; длина и смещение данных) + сами картинки; с Vista внутрь можно кладать PNG — им и пользуемся.

### v1.2.443 — ЗНАК ПРИЛОЖЕНИЯ: своя иконка (трей + окно + установщик) и знак на экранах загрузки

**КОНТЕКСТ**: у приложения НЕ БЫЛО своей иконки вообще. Доказательство — журнал сборки v1.2.442: `default Electron icon is used, reason=application icon is not set` (это сообщение печатает сам electron-builder, `platformPackager.js: getOrConvertIcon` → когда `build.win.icon` не задан). В трее при этом рисовался просто синий круг цвета `rgb(42,171,238)` — телеграмный голубой, никак не связанный с продуктом. По макетам (плиты 01–03, обсуждались с пользователем) выбран вариант **№02 «Сходящиеся линии», оттенок «Лазурь»**: белая реплика с хвостиком + три лазурные полосы (#38BDF8) на тёмной плитке.

**ЕДИНЫЙ ИСТОЧНИК РИСУНКА** — новый корневой [shared/appIconMark.js](../../shared/appIconMark.js) (212/300):
• `drawMark({size, order, tile, pad})` рисует знак в буфер картинки: сглаживание пробами по сетке (SS×SS на пиксель), фигуры считаются через расстояния (отрезок → полосы с круглыми концами, знаковое расстояние до скруглённого прямоугольника → контур пузыря, половинные плоскости → хвостик). `order: 'bgra'` — для Electron на Windows, `'rgba'` — для файла.
• `encodePNG` / `markPNG` — свой кодировщик PNG (подпись + IHDR + IDAT + IEND, таблица CRC32, сжатие встроенным `node:zlib`). **Новых зависимостей НЕ добавлено** — в проекте уже был приём «рисуем картинку в буфер руками» ([overlayIcon.js](../../main/utils/overlayIcon.js) так делает бейдж).
• Геометрия задана ОДИН раз (пузырь `22,10,38×34,r11`; полосы `x 3→17` на `y 18/32/46`; хвостик `31,44 → 31,57 → 43,44`) — те же числа стоят в разметке обеих заставок, и это закреплено тестом «геометрия одинаковая в трёх местах».
