## 1. Симптом

На экране висит стопка карточек уведомлений. **Ни одна кнопка не реагирует** — ни крестик, ни «Перейти в
чат», ни «Прочитано», ни 📌. Само окно при этом живое: главная программа каждые 15 секунд спрашивает
у него размер, и оно отвечает. Карточки внутри здоровые (непрозрачные, для мыши открытые).
Лечится только перезапуском программы — и после перезапуска первое же нажатие работает.

Простыми словами: телевизор показывает картинку, но пульт к нему не доходит.

Настройка «Время показа уведомления = бесконечно» (`notifDismissSec = 0`) — **выбор пользователя,
не дефект**. Она лишь делает беду заметной: карточки не уходят сами, и мёртвые кнопки видны.

- ❌ **«Регрессия кода»** — правок окна между рабочим и нерабочим днём нет.

## 6. Документация (собрано 2026-09-19)

### Официальная документация Electron (версия в проекте — 42.5.0; типы `node_modules/electron/electron.d.ts`)

- **`focusable`**: «Whether the window can be focused. Default is `true`. On Windows setting `focusable: false`
  also implies setting `skipTaskbar: true`.» — про мышь ничего.
- **`setAlwaysOnTop(flag, level, relativeLevel)`**: «Sets whether the window should show always on top of
  other windows. After setting this, the window is still a normal window, not a toolbox window which
  can not be focused on.» Уровни: «from `floating` to `status` … below the taskbar on Windows. From
  `pop-up-menu` to a higher it is shown above … the taskbar on Windows» → `screen-saver` = выше
  панели задач. Про частоту вызовов — ничего.
- **`setIgnoreMouseEvents(ignore, {forward})`**: «Makes the window ignore all mouse events. All mouse events
  happened in this window will be passed to the window below…» — в проекте **не используется** у окна
  уведомлений (ловушка #21, страж `transparentWindowGuard.test.cjs`).
- **Прозрачные окна — ограничения** (Custom Window Styles → Limitations): «You cannot click through the
  transparent area» (issue #1335); «Transparent windows are not resizable. Setting `resizable` to `true`
  may make a transparent window stop working on some platforms»; «The window will not be transparent
  when DevTools is opened»; Windows: «Transparent windows can not be maximized using the Windows system
  menu or by double clicking the title bar». → у нас `resizable:false` ✅; DevTools в окне не открываем ✅.
- **`webContents` событие `'input-event'`**: «Emitted when an input event is sent to the WebContents» —
  на нём построен уровень 1 наблюдателя. Поля `MouseInputEvent`: `type` (`mouseDown|mouseUp|mouseEnter|
  mouseLeave|contextMenu|mouseWheel|mouseMove`), `x`, `y`, `button`, `globalX/globalY`.
- **События окна `'unresponsive'` / `'responsive'`**: «Emitted when the web page becomes unresponsive» —
  подключены.
- **`screen.getCursorScreenPoint()`** — положение курсора системы; на нём построен уровень 3
  («курсор над окном, а событий нет»).
- **`showInactive()`**: «Shows the window but doesn't focus on it» — так окно и показывается.

### Похожие жалобы в трекере Electron (НЕ официальная дока — улики, не факты)

- [#44474 Mouse Events Malfunction When alwaysOnTop is Enabled](https://github.com/electron/electron/issues/44474) —
  macOS, Electron 33: при `alwaysOnTop` окно «stops responding to certain mouse events … until the cursor is
  moved outside the window and then brought back in». Помечено «Fixed for Next Release» (33/34). У нас 42 —
  фикс уже внутри, и ОС другая. Ценно совпадение симптома: **мышь возвращается после ухода курсора за
  границы окна** — стоит проверить руками при следующем случае.
- [#21459 Setting focusable:false breaks the focus event](https://github.com/electron/electron/issues/21459) —
  `focusable:false` ломает события фокуса; не про мышь, но показывает, что такое окно ведёт себя особо.
- [#31536 setAlwaysOnTop(false)→(true) сбивает «поверх всех» у ДРУГИХ окон](https://github.com/electron/electron/issues/31536) —
  предупреждение к шагу самопроверки `topmost-toggle`: у дока/подсказки есть своя «пружина», они поднимутся сами.
- [#34353 setIgnoreMouseEvents ведёт себя неожиданно, когда другое окно Electron в фокусе](https://github.com/electron/electron/issues/34353) —
  к нам не относится напрямую (не используем), оставлено для полноты.

## 8. Как разбирать следующий случай (пошагово)

1. Не перезапускать сразу. Проверить руками и записать сюда: (а) нажать карточку — среагировала ли
   программа ПОД ней; (б) увести курсор за границы окна и вернуть — оживились ли кнопки (симптом #44474);
   (в) крутится ли колесом стопка.
2. Открыть журнал `%APPDATA%\ЦентрЧатов\chatcenter.log` и достать за нужный час строки
   `[notif-input]`, `[notif-renderer] page:`, `close-click`, `закрытие НЕ началось`, `[notif-window]`.
3. По ленте `состояние:` найти момент, когда `move=… down=…` стали нулями при курсоре `НАД окном` — это
   время начала беды. Что было в журнале в ту минуту (новая карточка? `CLAMP`? событие окна?).
4. Свериться с таблицей диагноза (раздел 7). Записать в раздел 10.
5. Только теперь — лечить по диагнозу (не по догадке).

`page: mousedown`. Если строк нет — наблюдатель мёртв, дело не двигается (проверить первым).

## 11. Когда закрывать дело

Диагноз подтверждён журналом хотя бы одного случая → лечение → следующий случай НЕ наступил в течение
4 недель при обычной работе → статус ✅, файл остаётся как история (переносить в `archive/` по
правилам проекта), грабля и ADR записаны.
