**Как пользоваться при новой жалобе** (порядок отработан на разборах 2026-09-15):
1. Спросить время и мессенджер → открыть `%APPDATA%/ЦентрЧатов/chatcenter.log`.
2. Найти минуту жалобы и посмотреть, СКОЛЬКО было строк `[NotifManager] show` — это число
   реально показанных карточек. Больше одной на событие = дубль.
3. По таблице меток ниже понять, КТО прислал каждую.
4. Сверить с разделом своего мессенджера — возможно, это уже известная беда.
5. Новое наблюдение дописать в «Журнал наблюдений» внизу.

## 1. Общая схема: как рождается уведомление

Два принципиально разных мира:

```
РОДНОЙ Telegram (через TDLib, вкладка «Общий чат»)
  TDLib → разбор сообщения (tdlibMapper.js) → состояние приложения
        → nativeStoreIpc.js решает «показывать ли» → app:custom-notify → окно

ВЕБ-МЕССЕНДЖЕРЫ (Telegram Web, МАКС, ВК, WhatsApp, Ozon — каждый в своём <webview>)
  страница мессенджера
    ├─ хук мессенджера (max.hook.js / vk.hook.js / …) → console.log('__CC_NOTIF__…')
    ├─ общий наблюдатель «QUICK» (monitor.preload.cjs) → ipc 'new-message'
    └─ запасной наблюдатель (monitor.preload.cjs) → console.log('__CC_MSG__…')
         ↓ всё сходится в ОДНОМ узле
    webviewHandleNewMessage.js (мьют → повторы → спам → звук) → app:custom-notify → окно
```

🔴 **ГЛАВНОЕ, ЧТО НАДО ПОНИМАТЬ**: у одного веб-мессенджера может быть **до трёх независимых
«доносчиков»**, и они НЕ знают друг о друге. Каждый сам решает, что «пришло новое сообщение».
Именно отсюда берутся дубли.

### Защита от повторов — где она и как устроена

Живёт в `src/utils/webviewHandleNewMessage.js`, сами правила — в `src/utils/messageProcessing.js`:

| Правило | Что делает | Окно времени |
|---|---|---|
| `isDuplicateExact` | точно такой же текст уже был | 10 секунд |
| `isDuplicateSubstring` | один текст является КУСКОМ другого (в любую сторону) | 5 секунд |
| `isOwnMessage` | это наше собственное отправленное | — |

🔴 **КЛЮЧЕВОЕ ОГРАНИЧЕНИЕ**: ключ сравнения складывается из **имени отправителя** и текста
(`buildMessageDedupScope`). Если два пути назвали отправителя ПО-РАЗНОМУ — сравнение вообще
не состоится, и оба уведомления пройдут. Это не теория: см. случай МАКС от 2026-09-15 ниже.

## 2. Метки в журнале (что грепать)

| Метка | Где рождается | Что означает |
|---|---|---|
| `[NotifManager] show` | `main/handlers/mainIpcHandlers.js` | **карточка реально показана**. Считать их — самый быстрый способ понять, сколько дублей |
| `[notif-ipc] custom-notify recv` | `main/handlers/mainIpcHandlers.js` | запрос на показ дошёл до главного процесса; видно `sender=`, `bodyLen=` |
| `[native-notif] emit` | `src/native/store/nativeStoreIpc.js` | РОДНОЙ Telegram решил показать; `bodyLen=0` = тело пустое |
| `[native-notif] skip muted` / `skip backlog` | там же | сознательно НЕ показали (заглушённый чат / старьё при старте) |
| `[tdlib-empty]` | `main/native/backends/tdlibMapperMedia.js` | вид сообщения не разобран → пустой пузырь (добавлено v1.2.461) |
| `[TRACE] … Источник:` / `Обработка:` / `Ribbon:` | `src/utils/…` трассировка | путь одного уведомления по шагам; в `Источник` виден `src=` |
| `[TRACE] … dedup … block` | `webviewHandleNewMessage.js` | повтор ПОЙМАН. **Ноль таких строк при видимых дублях = защита не сработала** |
| `[MAX-QUICK]` | `main/preloads/monitor.preload.cjs` | общий быстрый наблюдатель (подробности включены для МАКС) |
| `[MAX-SNAPSHOT]` | `main/preloads/utils/maxDiagnostics.js` | снимок страницы МАКС: размеры, строки списка, заголовок |
| `[notif-resize]`, `[notif-watchdog]` | `main/handlers/notifHandlers.js` | размер/скрытие окна уведомлений, сторож «невидимой стены» |
| `__CC_DIAG__*` | хуки мессенджеров | временная диагностика внутри чужой страницы |

## 3. По мессенджерам

### 3.1 Telegram — РОДНОЙ (TDLib, «Общий чат»)

**Доносчик один**: `src/native/store/nativeStoreIpc.js` по событию нового сообщения от TDLib.
Дублей по устройству быть не должно — путь единственный.

**Что берётся в текст**: `message.text`, а если его нет — подпись по виду вложения
(`🖼 Фото`, `📹 Видео`, `📎 вложение` и т.п.). Если пусто и то и другое → **`[медиа]`**.

**Известные беды**:

| Дата | Симптом | Корень | Статус |
|---|---|---|---|
| 2026-09-15 | `[медиа]` в уведомлении, пустой пузырь в чате, «вложение» в списке чатов | вид сообщения не разобран в `extractMediaInfo` (знает 16 видов); текста не было. Три надписи — потому что ТРИ разных составителя, у каждого своя заглушка | 🟡 запись в журнал добавлена (v1.2.461), сам вид ещё не назван |

🔴 **Ловушка для будущего**: у родного Telegram подпись для СПИСКА ЧАТОВ строит отдельный файл
(`main/native/backends/tdlibPreview.js`, своя таблица видов), а для УВЕДОМЛЕНИЯ — другой
(`nativeStoreIpc.js`). Списки видов у них РАЗНЫЕ. Поэтому «в списке одно, в уведомлении другое» —
нормальное следствие, а не отдельная поломка.

**Проверять так**: `grep "native-notif. emit" chatcenter.log` — если `bodyLen=0`, тело было пустым
на входе, и искать надо в разборе сообщения, а не в окне уведомления.

## 4. Чего не хватает, чтобы разбирать быстрее (мой список)

Честный перечень того, чего мне НЕ хватило при разборах 2026-09-15. Это не задачи «сделать
сейчас», а список пробелов — чтобы следующий разбор не начинался с нуля.

| № | Чего не хватает | Почему это тормозит разбор | Важность |
|---|---|---|---|
| 1 | В журнале **не видно, какой из путей** прислал карточку | приходится сопоставлять по времени и тексту вручную; при трёх доносчиках это гадание | ⭐⭐⭐⭐⭐ |
| 2 | Защита от повторов пишет, только когда **поймала**. Когда ПРОПУСТИЛА — молчит | нельзя понять, почему дубль прошёл: ключ не совпал? окно времени вышло? до правила вообще не дошло? | ⭐⭐⭐⭐⭐ |
| 3 | Нет записи «сырое имя отправителя → очищенное» | задвоенное имя МАКС нашлось случайно; если бы писалось — увидели бы сразу | ⭐⭐⭐⭐ |
| 4 | Нет одной строки-итога на событие («показано N карточек за 2 секунды из источников A, B, C») | считать `[NotifManager] show` руками приходится глазами | ⭐⭐⭐ |
| 5 | Незнакомый вид сообщения родного Telegram записан (v1.2.461), но **сам вид всё ещё неизвестен** | нужен один запуск с открытием нужного чата | ⭐⭐⭐⭐ |

### 2026-09-15 — МАКС: три карточки на один файл 🔴 открыто

- **Что видел пользователь**: три одинаковых уведомления подряд про файл `check.pdf` от
  «Бузов Алексей Николаевич», плюс в одном из них имя написано дважды.
- **Что в журнале** (17:13:44–45): три показа — `id=17` текст `check.pdf` (источник
  `max-sidebar`), `id=18` текст «Новые сообщения PDF check.pdf Скачать • 9.17 KB» с задвоенным
  именем (источник `MAX-QUICK`), `id=19` тот же длинный текст через секунду (после
  «обогащения»). **Блокировок повторов за весь день — ноль.**
- **Вывод**: сработали три независимых доносчика; защита не связала их, потому что ключ
  сравнения включает имя отправителя, а один путь его задваивает.
- **Не установлено**: почему третья карточка (с ПРАВИЛЬНЫМ именем и текстом, содержащим
  `check.pdf`) не была отсечена правилом «один текст — кусок другого». По коду оно должно было
  сработать. **(не воспроизведено)**
- **Следующий шаг**: запись о том, почему защита пропускает (пробел №2 выше).

### 2026-09-15 — Родной Telegram: `[медиа]` вместо содержимого 🟡 частично

- **Что видел пользователь**: уведомление `[медиа]` от канала Forbes Russia; в чате на этом
  месте пузырь только с шапкой «Переслано от неизвестно», без содержимого; в списке чатов —
  «вложение».
- **Что в журнале** (16:34:38): `[native-notif] emit … bodyLen=0` — тело пустое НА ВХОДЕ.
  Таких случаев за день три: Forbes Russia ×2, HUAWEI | HarmonyOS ×1.
- **Вывод**: вид сообщения не разобран; три надписи — три разных составителя с разными заглушками.
- **Опровергнуто по ходу**: версия «текст есть, но теряется» — подпись берётся общим правилом
  для любого вида, значит подхватилась бы.
- **Сделано**: запись `[tdlib-empty]` с названием вида, один раз на вид (v1.2.461).
- **Ожидает**: один запуск с открытием чата Forbes Russia → в журнале появится название вида.
