# Обзор доработки — AI-агент

## Цель

Сделать так чтобы AI **не только давал советы по тексту**, а **сам выполнял действия** с
уведомлениями и сообщениями:

- Точно определял источник сообщения (аккаунт + чат + сообщение + отправитель)
- Мог переходить к нужному сообщению
- Мог писать ответы (с подтверждением)
- Мог создавать задачи и напоминания
- Мог читать историю чата для контекста
- Был безопасен (нельзя дать AI неконтролируемо отправлять)

## Что юзер получит после доработки

### Сейчас (до доработки)

```
[уведомление от клиента "Здравствуйте, как заказать?"]
   ↓
Юзер кликает «AI» → копирует текст вручную
   ↓
AI генерирует 3 варианта ответа
   ↓
Юзер копирует подходящий вариант
   ↓
Юзер открывает чат вручную
   ↓
Юзер вставляет текст и отправляет
```

**Время**: ~30 секунд. **Действия**: 5+ кликов.

### После доработки

```
[уведомление от клиента "Здравствуйте, как заказать?"]
   ↓
Юзер кликает «🤖 Обработать»
   ↓
AI читает 10 предыдущих сообщений → анализирует → предлагает:
  • Ответ: «Здравствуйте, Иван! Для заказа...»
  • Задача: «Перезвонить Ивану завтра 10:00»
   ↓
Юзер кликает [✓ Отправить] [✓ Создать задачу]
   ↓
AI отправляет в нужный чат + создаёт задачу
```

**Время**: ~5 секунд. **Действия**: 2 клика.

## Область проекта (что входит)

### ✅ Входит в проект

- NotificationSource — паспорт каждого сообщения (откуда / кому / что)
- Action Bus — единая шина действий для юзера и AI
- Tool Use — AI вызывает функции по JSON Schema
- Permission система (auto / confirm / deny)
- Cross-tab уведомления (работают с любой вкладки)
- AI читает контекст чата для анализа
- AI отправляет ответы (через подтверждение)
- Создание задач и напоминаний через AI
- Audit log AI действий

### ❌ Не входит в проект (отложено)

- Голосовое управление AI
- Перевод сообщений на лету
- AI определение тональности с emoji-реакциями
- AI auto-modration (бан-листы)
- Voice transcription
- Image generation в чатах
- Полная замена оператора (AI отвечает без подтверждения)

## 5 фаз доработки

### Phase 0 — Фундамент

**Что**: NotificationSource (паспорт) + Action Bus + Cross-tab fix

**Зачем**: Без этого AI не может знать откуда сообщение. Все остальные фазы зависят.

**Объём**: ~150 строк нового, ~30 удалить из существующих файлов
**Срок**: ~2 часа работы
**Что появится у юзера**: уведомления работают с любой вкладки (cross-tab fix решён)
**Детали**: [phases/phase-0-foundation.md](./phases/phase-0-foundation.md)

### Phase 1 — Tool Use каркас

**Что**: Реестр инструментов, JSON Schema, 3 базовых tools (read-only)

**Зачем**: Каркас для AI. AI ещё не пишет/удаляет, только читает.

**Объём**: ~300 строк нового
**Срок**: ~3-4 часа работы
**Что появится у юзера**: AI «понимает» источник сообщения, может читать историю чата
**Детали**: [phases/phase-1-tools.md](./phases/phase-1-tools.md)

### Phase 2 — Write actions + Permissions

**Что**: reply_to_message, create_task + permission система + audit log

**Зачем**: AI может действовать с подтверждением юзера. Безопасно.

**Объём**: ~400 строк
**Срок**: ~4-5 часов работы
**Что появится у юзера**: AI может отправлять ответы (юзер кликает [Подтвердить])
**Детали**: [phases/phase-2-permissions.md](./phases/phase-2-permissions.md)

### Phase 3 — UI агента

**Что**: Кнопка «🤖 Обработать», multi-turn reasoning, streaming, AI Activity UI

**Зачем**: Юзеру удобно работать с AI как с агентом.

**Объём**: ~400 строк
**Срок**: ~4-5 часов работы
**Что появится у юзера**: одна кнопка «🤖 Обработать» делает всё
**Детали**: [phases/phase-3-agent-ui.md](./phases/phase-3-agent-ui.md)

### Phase 4 — Расширения (опционально)

**Что**: Tasks panel, Reminders, AI auto-reply rules, Ollama для офлайн

**Зачем**: Полноценный продукт.

**Объём**: ~800 строк
**Срок**: ~1-2 недели работы
**Что появится у юзера**: задачи / напоминания / AI работает офлайн через Ollama
**Детали**: [phases/phase-4-extensions.md](./phases/phase-4-extensions.md)

## Критерии успеха

### Минимальный успех (Phase 0+1)

- [ ] Юзер может кликнуть на уведомление с любой вкладки → попадает на сообщение
- [ ] AI «видит» точный источник сообщения (accountId/chatId/messageId/senderName)
- [ ] AI может читать историю чата для контекста
- [ ] Все тесты проходят
- [ ] Никаких регрессий в существующем функционале

### Полный успех (Phase 2+3)

- [ ] AI предлагает ответ с одним кликом подтверждения от юзера
- [ ] AI создаёт задачи с подтверждением
- [ ] Permission система работает (auto / confirm / deny per tool)
- [ ] Audit log записывает все AI действия
- [ ] UI агента работает с любого провайдера (OpenAI / Claude / DeepSeek)

### Идеальный успех (Phase 4)

- [ ] AI работает офлайн через Ollama
- [ ] Auto-reply правила через AI
- [ ] История + статистика AI действий
- [ ] Tasks UI полностью функциональна

## Принципы доработки

1. **Минимум touch** — переиспользовать существующую AI-инфраструктуру (AISidebar, aiHandlers).
2. **Без новых npm зависимостей** — нативный fetch / SSE / IPC.
3. **Безопасность по умолчанию** — write actions требуют confirm.
4. **Обратная совместимость** — старый AI-чат (текстовые suggestions) продолжает работать.
5. **Каждый шаг — проверка** — без подтверждения юзера не двигаться.
6. **Документация в .memory-bank** — все решения и проблемы зафиксированы.
7. **Regression-тесты обязательны** — каждая фаза = +N тестов.

## Out of scope (что не делаем)

- Замена существующего AISidebar.jsx (остаётся как «текстовый помощник»)
- Внешние сервисы / cloud backends (всё локально)
- Подписочные модели / монетизация (это для будущего)
- Изменение архитектуры мессенджеров (TDLib / webview остаются как есть)
